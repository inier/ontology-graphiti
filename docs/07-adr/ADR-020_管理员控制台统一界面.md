# ADR-020: 管理员控制台统一界面

> **来源**: `docs/ARCHITECTURE.md` 第 17 章
> **扩展**: 2026-05-07 深化 UI 设计 (原 50 行 → 本版 300+ 行)

**状态**: 已接受 | **日期**: 2026-04-16

---

## 1. 上下文

系统需要管理员控制台，用于：
- 系统配置管理中心（全局参数、LLM Provider、Embedding 选择）
- 用户与角色管理（用户 CRUD、角色绑定、工作空间分配）
- 监控告警管理（告警规则配置、通知渠道配置）
- 日志与审计查看（操作日志、审计日志、链路追踪）
- 工作空间模板库（模板管理、模板化一键创建）

当前控制台仅有概念性描述，缺乏具体的 UI 布局、组件设计和交互流程定义。

---

## 2. 决策

构建**管理员控制台**，基于 React + Ant Design 6 + Zustand 状态管理，采用统一的 SPA 内嵌路由。

### 2.2 各模块详细设计

#### 2.2.1 配置中心（核心）

**分组结构**:
```
配置组
├── LLM 配置
│   ├── Commander 模型: GPT-4 / Claude-3.5-Sonnet
│   ├── Intelligence 模型: DeepSeek-v3 / Kimi
│   ├── Operations 模型: GPT-4o-mini / Qwen
│   └── Embedding 模型: text-embedding-3-small / bge-m3
├── 图谱配置
│   ├── Neo4j URI + 认证
│   ├── Graphiti 配置 (episode window, max nodes)
│   └── 向量索引配置
├── 知识配置
│   ├── 默认 Chunk Size
│   ├── 默认 Chunk 策略 (paragraph/semantic)
│   ├── RAG Top-K
│   └── 实体抽取置信度阈值
└── 安全配置
    ├── Session 超时 (15min)
    ├── 登录限流 (5次/15min)
    ├── API Key 默认过期 (90天)
    └── TLS 证书路径
```

**双模式编辑组件**:

```typescript
const ConfigEditor: React.FC<{ groupId: string; onSave: (config: any) => void }> = ({ groupId, onSave }) => {
  const [mode, setMode] = useState<'form' | 'json'>('form')
  const [config, setConfig] = useState<Record<string, any>>({})
  const [isDirty, setIsDirty] = useState(false)
  const [versions, setVersions] = useState<ConfigVersion[]>([])

  const handleFieldChange = (key: string, value: any) => {
    setConfig(prev => ({ ...prev, [key]: value }))
    setIsDirty(true)
  }

  const handleSaveVersion = async () => {
    const version = await saveConfig(groupId, config, "管理员更新")
    setVersions(prev => [version, ...prev])
    setIsDirty(false)
    message.success("配置已保存，即将热生效")
  }

  const handleRollback = async (versionId: string) => {
    const oldConfig = await loadConfigVersion(groupId, versionId)
    setConfig(oldConfig)
    setIsDirty(true)
  }

  return (
    <div className="config-editor">
      <div className="config-editor-toolbar">
        <Button.Group>
          <Button type={mode === 'form' ? 'primary' : 'default'} onClick={() => setMode('form')}>
            表单模式
          </Button>
          <Button type={mode === 'json' ? 'primary' : 'default'} onClick={() => setMode('json')}>
            JSON 模式
          </Button>
        </Button.Group>
        <Space>
          <Button onClick={handleSaveVersion} type="primary" disabled={!isDirty}>
            保存新版本
          </Button>
          <Badge count={versions.length} size="small">
            <Button icon={<HistoryOutlined />} onClick={() => setShowVersions(true)}>
              版本历史
            </Button>
          </Badge>
        </Space>
      </div>

      {mode === 'form' ? (
        <Form layout="vertical">
          {configSchema[groupId]?.fields.map(field => (
            <Form.Item key={field.key} label={field.label} help={field.description}>
              {renderField(field, config[field.key], (v) => handleFieldChange(field.key, v))}
            </Form.Item>
          ))}
        </Form>
      ) : (
        <JsonEditor
          value={config}
          onChange={(newVal) => { setConfig(newVal); setIsDirty(true) }}
          height={400}
        />
      )}

      <VersionHistoryModal
        open={showVersions}
        versions={versions}
        onRollback={handleRollback}
        onDiff={(v1, v2) => {/* diff modal */}}
        onClose={() => setShowVersions(false)}
      />
    </div>
  )
}
```

#### 2.2.2 用户管理

| 列 | 类型 | 操作 |
|------|------|------|
| 用户名 | 文本 + 头像 | — |
| 认证方式 | Tag (本地/SSO) | — |
| 全局角色 | Select (admin/commander/analyst/operator/observer) | 可编辑 |
| 工作空间 | Tag 列表 (ws_name: role) | 可编辑弹窗 |
| 状态 | Switch (启用/禁用) | 可切换 |
| 最后登录 | 时间 | — |
| 操作 | Button 组 | 编辑 / 重置密码 / 删除 |

用户详情弹窗包含标签页：
- **基本信息**: 用户名、邮箱、认证方式、创建时间
- **工作空间**: 绑定列表 + 角色分配 (Table + 内联编辑)
- **API Keys**: 已创建的 Key 列表、创建新 Key、吊销
- **操作审计**: 该用户的操作记录 (联动审计日志模块)

#### 2.2.3 角色管理

```typescript
interface RoleTemplate {
  name: string          // "指挥官" / "情报分析员" / "操作员"
  key: string           // commander / analyst / operator
  permissions: string[]  // ["workspace:read", "ontology:read", "entity:attack", ...]
  inherits: string[]    // 可继承的基础角色
  description: string
}
```

角色编辑采用权限矩阵视图：行=权限点(action:resource)，列=角色，单元格=Checkbox

#### 2.2.4 工作空间管理

管理员视角下的工作空间列表，比普通用户多出：
- **资源配额编辑**: 节点数上限、存储上限、并发推演数
- **所有者变更**: 转移工作空间所有权
- **归档/恢复**: 管理已归档空间
- **批量操作**: 多选后进行批量归档/删除

#### 2.2.5 监控告警配置

| 配置项 | 组件 | 说明 |
|------|------|------|
| 告警规则状态 | Switch 列表 | 启用/禁用特定告警规则 |
| 告警阈值 | InputNumber | 如 P95 延迟阈值从 3s → 2s |
| 通知渠道 | Checkbox 组 | 企业微信 / 邮件 / Webhook |
| Webhook URL | Input | 自定义 Webhook 地址 |
| 静默时段 | TimeRangePicker | 维护窗口期间静默告警 |
| 通知模板 | TextArea | 告警消息模板 |

## 3. 后果

| 正面 | 负面 |
|------|------|
| ✅ 统一管理入口，降低 90% 配置复杂度 | ❌ 初期开发工作量约 15 人日 |
| ✅ 配置热生效，无需重启 | ❌ 双模式编辑器增加前端复杂度 |
| ✅ 版本可追溯，变更可回滚 | ❌ 需要严格的权限控制（admin 角色隔离） |
| ✅ 审计日志可联动跳转 | |
| ✅ 告警规则可视化配置 | |

---

## 4. 可逆性

**低-中**。控制台是 Admin UI 的基础设施层，一旦建成将是后续所有管理功能的承载平台，建议一次性完善。
