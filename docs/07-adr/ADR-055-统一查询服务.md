# ADR-055: 统一查询服务 (QueryService)

## 状态
提议

## 上下文

当前 ODAP 存在 5 条独立的图谱查询路径：

1. **SelfCorrectingOrchestrator (v1)**: 正则硬编码路由，完全不查询图谱
2. **DomainSwarm (OODA)**: 仅在 Orient 阶段调用 `retrieve_rag_context()`
3. **IntelligenceAgent (ReAct)**: 调用 `retrieve_rag_context()` + SKILL_CATALOG
4. **UserCognitionEngine**: `KnowledgeNavigator` 与 `GraphManager` 接口断裂，实际无法工作
5. **frontend_compat API**: 直接调用 `graph_manager.search()`

问题：
- 意图识别重复实现 4 次，且两个 IntentRecognizer 定义了不同的意图枚举
- KnowledgeNavigator 期望的接口（get_neighbors / get_related_entities / get_node_properties）与 GraphManager 实际方法完全不匹配
- 所有查询方法返回 List[Dict]，无结构化类型
- Agent 可直接调用 graph_manager.add_entity()，无安全边界
- GraphManager 缺少 get_neighbors() / traverse() 等图遍历方法

阿里巴巴 UModel 项目提供了成熟的解决方案：
- **Query First**: 所有读取走 QueryService，禁止散落的域读取端点
- **Query Surface**: `.umodel` / `.entity` / `.topo` 三种查询源
- **Agent Safe**: 默认只读，写工具需显式启用
- **Architecture Guard**: 自动化测试强制执行边界规则

## 决策

借鉴 UModel 的 Query Surface 设计模式，在 ODAP 内部构建统一的 QueryService：

1. **定义四种查询源**：`.schema`（OMS 类型定义）、`.entity`（运行时实体）、`.topo`（拓扑关系）、`.temporal`（双时态数据，ODAP 独有）
2. **新建 `odap/infra/query/` 模块**：实现 QueryService + Parser + Source 抽象
3. **为 GraphManager 补充图遍历方法**：`get_neighbors()` / `traverse()`
4. **通过 OpenHarness Tool 接口注册查询工具**：Agent 统一走 QueryService
5. **实现架构守卫**：pytest 测试强制执行 Query First 规则

### 与 OpenHarness 的集成

QueryService 通过 OpenHarness 的 Tool 接口注册为 Agent 可用工具：
- 查询工具（query_schema / query_entity / query_topo / query_temporal）标记为 `safety="read"`
- 写操作工具（write_entity / write_relation）通过 PreToolUse Hook 调用 OPA 校验
- OpenHarness Swarm Coordinator 中的三 Agent 统一使用 QueryService 工具

### 实施路径

| 阶段 | 内容 | 风险 |
|------|------|------|
| Phase 1 | 新建 QueryService，不破坏现有代码 | 低 |
| Phase 2 | Agent 统一走 QueryService，废弃分散路径 | 中 |
| Phase 3 | MCP Server 集成，外部 Agent 通过标准协议访问 | 低 |

## 后果

**正面**：
- 消除 5 条分散查询路径，统一为 1 个入口
- 修复 KnowledgeNavigator 与 GraphManager 的接口断裂
- Agent 获得结构化查询结果（QueryResult 而非 List[Dict]）
- 实现 Agent Safe 默认只读，写操作需 OPA 审批
- 架构守卫防止未来再次出现查询路径分散

**负面**：
- 现有 Agent 需要逐步迁移到 QueryService
- GraphManager 需要补充 get_neighbors() / traverse() 方法
- 查询语法解析器需要持续维护

## 可逆性
高。QueryService 是新增模块，不修改现有代码。可通过配置开关切换新旧路径。
