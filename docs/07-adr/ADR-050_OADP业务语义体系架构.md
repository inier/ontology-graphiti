# ADR-050: OADP 业务语义体系架构

> **分析日期**: 2026-04-23
> **分析目的**: 基于 OADP（感知-理解-决策-执行）业务语义体系，审查当前设计的一致性
> **参考文档**: req-ok.md v2.0.0, ARCHITECTURE.md v3.2

---

## 一、OADP 业务语义定义

### 1.1 OADP 闭环模型

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    OADP 闭环：感知 → 理解 → 决策 → 执行                       │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│    ┌─────────┐    ┌─────────┐    ┌─────────┐    ┌─────────┐             │
│    │   感知   │───►│   理解   │───►│   决策   │───►│   执行   │             │
│    │Observe  │    │Analyze  │    │  Decide  │    │Perform  │             │
│    └────┬────┘    └────┬────┘    └────┬────┘    └────┬────┘             │
│         │              │              │              │                    │
│         ▼              ▼              ▼              ▼                    │
│    ┌────────┐    ┌────────┐    ┌────────┐    ┌────────┐               │
│    │数据采集 │    │本体构建 │    │策略校验 │    │行动更新 │               │
│    │外部情报 │    │知识图谱 │    │方案推荐 │    │状态回写 │               │
│    │多模态  │    │模式识别 │    │风险评估 │    │审计记录 │               │
│    │摄入    │    │检索推理 │    │OPA审批  │    │闭环反馈 │               │
│    └────────┘    └────────┘    └────────┘    └────────┘               │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 1.2 OADP 各阶段职责

| 阶段 | 英文 | 核心职责 | 输入 | 输出 |
|------|------|----------|------|------|
| **感知** | Observe | 数据采集、外部情报获取、多模态数据摄入 | 原始数据流 | 结构化事件 |
| **理解** | Analyze | 本体构建、知识图谱组织、模式识别、语义检索 | 结构化事件 | 关联分析、评估 |
| **决策** | Decide | 策略校验、方案生成、风险评估、方案推荐 | 理解结果 | 决策建议、行动指令 |
| **执行** | Perform | 行动实施、状态更新、审计记录、闭环反馈 | 行动指令 | 执行结果、状态变更 |

## 二、当前设计与 OADP 对齐分析

### 2.1 OADP 组件映射表

| OADP 阶段 | 目标能力 | 当前模块 | 对齐状态 | 说明 |
|-----------|----------|----------|----------|------|
| **感知 Observe** | 数据采集与摄入 | MCP Protocol、Data Ingestion、Event Simulator | ⚠️ 部分 | 有设计，但缺乏统一的感知层抽象 |
| | 多模态数据接入 | Multi-modal Processor | ⚠️ 概念层 | 仅 ADR-010/019 有描述，无独立模块 |
| **理解 Analyze** | 本体构建与管理 | Ontology Management | ✅ 完整 | M-03，完整实现 |
| | 知识图谱存储 | Graphiti Client | ✅ 完整 | M-01，完整实现 |
| | 语义检索与推理 | QA Engine | ✅ 部分 | M-12，部分实现 |
| **决策 Decide** | 策略治理 | OPA Policy | ✅ 完整 | M-02，完整实现 |
| | 决策推荐 | Decision Recommendation | ❌ 未实现 | M-13，有设计文档但无代码 |
| | Agent 编排 | Swarm Orchestrator | ✅ 部分 | M-09，基础功能实现 |
| **执行 Perform** | 行动执行 | Skills / Tool Registry | ✅ 部分 | M-08/M-11，部分实现 |
| | 状态更新 | Graphiti Write | ✅ 完整 | Graphiti 原生支持 |
| | 审计记录 | Audit Log | ✅ 完整 | M-07，完整实现 |
| | 闭环反馈 | 无 | ❌ 缺失 | 缺少显式的反馈机制设计 |

### 2.2 问题识别

#### 🔴 高优先级问题

| # | 问题 | 影响 | 建议 |
|---|------|------|------|
| 1 | **OADP 术语不一致** | 文档使用 OODA，用户需求使用 OADP | 新增 ADR-050，统一术语 |
| 2 | **Decision Recommendation 无实现** | 决策阶段核心能力缺失 | 标记为 Phase 4 或补充基础实现 |
| 3 | **闭环反馈机制缺失** | OADP 无法形成真正闭环 | 新增反馈通道设计 |

#### 🟡 中优先级问题

| # | 问题 | 影响 | 建议 |
|---|------|------|------|
| 4 | **感知层抽象不足** | 数据摄入与感知混为一谈 | 明确感知层边界，设计感知接口 |
| 5 | **执行层 Action 反馈缺失** | 决策效果无法量化评估 | 增加执行结果回传机制 |
| 6 | **多模态数据接入模块化不足** | 仅概念设计，无独立模块 | 评估是否需要独立模块 |

## 三、OADP 架构缺口详细分析

### 3.1 感知层（Observe）缺口

**当前设计状态**:
- MCP Protocol（ADR-026）：外部系统集成协议 ✅
- Data Ingestion（FR-203）：多模态数据接入 ✅ 设计
- Event Simulator（M-15）：模拟事件生成 ✅ 部分实现

**缺口**:
1. **缺乏统一的感知抽象层**
   - 当前数据摄入直接写入 Graphiti，没有独立的"感知"概念
   - 建议：设计 `IObserver` 接口，抽象数据采集行为

2. **多模态处理分散**
   - PDF/图片/音视频处理散落在不同模块
   - 建议：统一到 `PerceptionService` 聚合处理

**建议架构**:

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                          感知层（Observe）                                    │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐     │
│  │ MCP Observer │  │ File Observer │  │ API Observer │  │Sensor Observer│     │
│  └──────┬──────┘  └──────┬──────┘  └──────┬──────┘  └──────┬──────┘     │
│         │                │                │                │               │
│         └────────────────┴────────────────┴────────────────┘               │
│                                    │                                        │
│                                    ▼                                        │
│                         ┌─────────────────┐                               │
│                         │  PerceptionHub   │                               │
│                         │  (感知聚合器)     │                               │
│                         └────────┬─────────┘                               │
│                                  │                                          │
│                                  ▼                                          │
│                         ┌─────────────────┐                               │
│                         │  EventEmitter   │                               │
│                         │  (事件发射器)    │                               │
│                         └────────┬─────────┘                               │
│                                  │                                          │
│                                  ▼                                          │
│                         ┌─────────────────┐                               │
│                         │  Graphiti       │                               │
│                         │  (知识图谱)      │                               │
│                         └─────────────────┘                               │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 3.2 理解层（Analyze）缺口

**当前设计状态**:
- Ontology Management（M-03）：本体管理 ✅
- Graphiti Client（M-01）：知识图谱 ✅
- QA Engine（M-12）：问答引擎 ✅ 部分

**缺口**:
1. **理解阶段的输出标准化不足**
   - 当前 QA Engine 输出不统一
   - 建议：定义 `AnalysisResult` 标准格式

2. **模式识别能力弱**
   - 仅有基础检索，无复杂模式识别
   - 建议：增加 Pattern Recognition 模块

### 3.3 决策层（Decide）缺口

**当前设计状态**:
- OPA Policy（M-02）：策略治理 ✅
- Decision Recommendation（M-13）：❌ 未实现

**缺口**:
1. **决策推荐核心缺失**
   - 有完整设计文档（`decision_recommendation/DESIGN.md`）
   - 但代码库无实现
   - 这是 OADP 决策阶段的关键能力

2. **决策链路不清晰**
   - 缺少从理解结果到决策建议的标准路径
   - 建议：设计 `DecisionPipeline`

**建议架构**:

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                          决策层（Decide）                                    │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  ┌─────────────┐    ┌─────────────┐    ┌─────────────┐                   │
│  │ Analysis    │───►│ Decision    │───►│ OPA         │                   │
│  │ Result      │    │ Generator   │    │ Validator   │                   │
│  └─────────────┘    └──────┬──────┘    └─────────────┘                   │
│                             │                                              │
│                             ▼                                              │
│                    ┌─────────────────┐                                     │
│                    │ Decision        │                                     │
│                    │ Recommender     │  ← 有设计，无实现                     │
│                    └────────┬────────┘                                     │
│                             │                                              │
│                             ▼                                              │
│                    ┌─────────────────┐                                     │
│                    │ Decision        │                                     │
│                    │ Result          │                                     │
│                    └────────┬────────┘                                     │
│                             │                                              │
│                             ▼                                              │
│                    ┌─────────────────┐                                     │
│                    │ Action          │                                     │
│                    │ Command         │                                     │
│                    └─────────────────┘                                     │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 3.4 执行层（Perform）缺口

**当前设计状态**:
- Skills / Tool Registry（M-08/M-11）：✅ 部分
- Audit Log（M-07）：✅ 完整
- Graphiti Write：✅ 完整

**缺口**:
1. **闭环反馈机制缺失**
   - 执行结果没有反馈到感知层形成闭环
   - 这是 OADP 与传统 OODA 的核心区别

2. **Action Result 回传机制缺失**
   - 决策到执行的结果没有标准反馈格式
   - 建议：设计 `ActionFeedback` 模型

**建议架构**:

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                          执行层（Perform）                                    │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  ┌─────────────┐    ┌─────────────┐    ┌─────────────┐                   │
│  │ Action      │───►│ Skill       │───►│ Graphiti     │                   │
│  │ Command     │    │ Executor    │    │ Writer      │                   │
│  └─────────────┘    └─────────────┘    └─────────────┘                   │
│                             │                                              │
│                             │  ┌─────────────┐                           │
│                             └──►│ Audit Log   │                           │
│                                └─────────────┘                           │
│                                                                             │
│  ┌─────────────────────────────────────────────────────────────────────┐ │
│  │                         闭环反馈通道                                   │ │
│  │  ┌─────────────┐    ┌─────────────┐    ┌─────────────┐              │ │
│  │  │ Action      │───►│ Feedback    │───►│ Perception  │              │ │
│  │  │ Result      │    │ Aggregator  │    │ Update     │              │ │
│  │  └─────────────┘    └─────────────┘    └─────────────┘              │ │
│  └─────────────────────────────────────────────────────────────────────┘ │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 四、术语统一建议

### 4.1 OODA vs OADP

| 原术语 | 新术语 | 说明 |
|--------|--------|------|
| OODA | OADP | 用户需求文档统一使用 OADP |
| Observe | 感知 | 外部数据采集 |
| Orient | 理解 | 本体驱动分析 |
| Decide | 决策 | 策略校验与方案推荐 |
| Act | 执行 | 行动实施与闭环反馈 |

### 4.2 术语对照表

| OADP 术语 | 等效描述 | 对应模块 |
|-----------|----------|----------|
| 感知层 | Observation Layer | MCP, Data Ingestion, Event Simulator |
| 理解层 | Analysis Layer | Ontology, Graphiti, QA Engine |
| 决策层 | Decision Layer | OPA, Decision Recommendation, Swarm |
| 执行层 | Execution Layer | Skills, Tool Registry, Audit Log |
| 闭环反馈 | Feedback Loop | 待新增 |

## 六、结论

### 6.1 对齐状态总结

| OADP 阶段 | 当前状态 | 缺口 |
|-----------|----------|------|
| 感知 Observe | ⚠️ 部分 | 缺乏统一抽象层 |
| 理解 Analyze | ✅ 良好 | 细节可优化 |
| 决策 Decide | ⚠️ 部分 | Decision Recommendation 未实现 |
| 执行 Perform | ✅ 部分 | 缺少闭环反馈 |

### 6.2 行动建议

**Phase 4 规划建议**:

1. **P0 - 必须完成**
   - [ ] 新增 ADR-050，统一 OADP 术语
   - [ ] 实现 Decision Recommendation 基础框架
   - [ ] 设计 Feedback Loop 机制

2. **P1 - 重要但可延后**
   - [ ] 设计感知层统一抽象
   - [ ] 优化理解层输出标准化
   - [ ] 实现执行结果回传

3. **P2 - 可选增强**
   - [ ] Pattern Recognition 模块
   - [ ] 多模态处理增强
