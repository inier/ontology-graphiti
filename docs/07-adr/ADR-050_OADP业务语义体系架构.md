# ADR-050: OADP 业务语义体系架构

## 状态

已接受

## 上下文

ODAP 平台基于 OADP（Observe-Analyze-Decide-Perform）业务语义体系构建，形成"感知→理解→决策→执行"的完整闭环。当前存在以下问题：

1. **术语不一致**：文档使用 OODA，用户需求文档使用 OADP，需统一术语
2. **闭环反馈缺失**：执行层完成后缺少显式的反馈机制，无法形成真正闭环
3. **感知层抽象不足**：数据摄入与感知混为一谈，缺乏统一的感知抽象层
4. **决策推荐未实现**：Decision Recommendation 有设计文档但无代码实现

需要将系统架构与 OADP 四阶段对齐，明确各阶段职责、组件映射和架构缺口。

## 决策

### 1. OADP 闭环模型

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    OADP 闭环：感知 → 理解 → 决策 → 执行                       │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│    ┌─────────┐    ┌─────────┐    ┌─────────┐    ┌─────────┐             │
│    │   感知   │───►│   理解   │───►│   决策   │───►│   执行   │             │
│    │Observe  │    │Analyze  │    │  Decide  │    │Perform  │             │
│    └────┬────┘    └────┬────┘    └────┬────┘    └────┬────┘             │
│         │              │              │              │                    │
│         ▼              ▼              ▼              ▼                    │
│    ┌────────┐    ┌────────┐    ┌────────┐    ┌────────┐               │
│    │数据采集 │    │本体构建 │    │策略校验 │    │行动更新 │               │
│    │外部情报 │    │知识图谱 │    │方案推荐 │    │状态回写 │               │
│    │多模态  │    │模式识别 │    │风险评估 │    │审计记录 │               │
│    │摄入    │    │检索推理 │    │OPA审批  │    │闭环反馈 │               │
│    └────────┘    └────────┘    └────────┘    └────────┘               │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 2. OADP 各阶段职责

| 阶段 | 英文 | 核心职责 | 输入 | 输出 |
|------|------|----------|------|------|
| **感知** | Observe | 数据采集、外部情报获取、多模态数据摄入 | 原始数据流 | 结构化事件 |
| **理解** | Analyze | 本体构建、知识图谱组织、模式识别、语义检索 | 结构化事件 | 关联分析、评估 |
| **决策** | Decide | 策略校验、方案生成、风险评估、方案推荐 | 理解结果 | 决策建议、行动指令 |
| **执行** | Perform | 行动实施、状态更新、审计记录、闭环反馈 | 行动指令 | 执行结果、状态变更 |

### 3. OADP 组件映射

| OADP 阶段 | 目标能力 | 当前模块 | 对齐状态 | 说明 |
|-----------|----------|----------|----------|------|
| **感知 Observe** | 数据采集与摄入 | MCP Protocol、Data Ingestion、Event Simulator | ⚠️ 部分 | 有设计，但缺乏统一的感知层抽象 |
| | 多模态数据接入 | Multi-modal Processor | ⚠️ 概念层 | 仅 ADR-010/019 有描述，无独立模块 |
| **理解 Analyze** | 本体构建与管理 | Ontology Management | ✅ 完整 | 完整实现 |
| | 知识图谱存储 | Graphiti Client | ✅ 完整 | 完整实现 |
| | 语义检索与推理 | QA Engine | ✅ 部分 | 部分实现 |
| **决策 Decide** | 策略治理 | OPA Policy | ✅ 完整 | 完整实现 |
| | 决策推荐 | Decision Recommendation | ❌ 未实现 | 有设计文档但无代码 |
| | Agent 编排 | Swarm Orchestrator | ✅ 部分 | 基础功能实现 |
| **执行 Perform** | 行动执行 | Skills / Tool Registry | ✅ 部分 | 部分实现 |
| | 状态更新 | Graphiti Write | ✅ 完整 | Graphiti 原生支持 |
| | 审计记录 | Audit Log | ✅ 完整 | 完整实现 |
| | 闭环反馈 | 无 | ❌ 缺失 | 缺少显式的反馈机制设计 |

### 4. 术语统一

| 原术语 | 新术语 | 说明 |
|--------|--------|------|
| OODA | OADP | 用户需求文档统一使用 OADP |
| Observe | 感知 | 外部数据采集 |
| Orient | 理解 | 本体驱动分析 |
| Decide | 决策 | 策略校验与方案推荐 |
| Act | 执行 | 行动实施与闭环反馈 |

### 5. 架构缺口与行动建议

**P0 - 必须完成**：
- 统一 OADP 术语
- 实现 Decision Recommendation 基础框架
- 设计 Feedback Loop 机制（见 ADR-051）

**P1 - 重要但可延后**：
- 设计感知层统一抽象（IObserver 接口）
- 优化理解层输出标准化（AnalysisResult 格式）
- 实现执行结果回传机制

**P2 - 可选增强**：
- Pattern Recognition 模块
- 多模态处理增强

## 后果

**正面**：
- OADP 四阶段职责清晰，组件映射明确
- 术语统一，与需求文档保持一致
- 架构缺口识别清楚，行动建议可执行

**负面**：
- 感知层统一抽象需要较大重构
- Decision Recommendation 实现需要额外开发资源
- 闭环反馈机制增加系统复杂度

## 可逆性

中。术语统一和组件映射调整可逆，但架构缺口修复（感知层抽象、闭环反馈）需要一定开发工作量。
