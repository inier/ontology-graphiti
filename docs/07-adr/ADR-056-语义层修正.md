# ADR-056: 语义层修正——类型校验执行化与模型统一

## 状态
提议

## 上下文

ODAP 语义层存在以下设计债务：

1. **OMS 类型定义与运行时实例之间的"桥"断了**：
   - `OntologyEntity.entity_type` 是自由字符串，不验证是否在 OMS 中注册
   - `Dict[str, Any]` 属性值不校验是否符合 PropertyDefinition 的类型/约束
   - LinkDefinition 的基数约束未执行
   - ActionTypeDefinition 的 OPA 策略未集成

2. **两套 OntologyDocument 定义**：
   - `schema/document.py`（dataclass 版）：完整实体/关系/事件/行动/规则/约束
   - `models/ontology_engine.py`（Pydantic 版）：简化为 entities/relations/properties，缺少 events/actions/rules/constraints

3. **Domain 模型与 OMS 语义重叠**：
   - `schema/domain.py` 的 ENTITY_TYPES 与 OMS 的 ObjectTypeDefinition 描述同一件事但结构不同
   - OMS 种子数据从 Domain 导入但格式转换有损

4. **类型继承未实现**：
   - ObjectTypeDefinition.parent_type 声明了父类型，但没有属性继承解析逻辑

5. **约束执行引擎缺失**：
   - PropertyDefinition.constraints 是开放式 Dict，但没有约束执行引擎

## 决策

### 修正 1：类型引用强制校验

在 QueryService 层实现读时校验（不改变写入路径的热写入性能）：

```python
class SchemaSourceImpl:
    def validate_entity_type(self, entity_type: str) -> bool:
        oms = SQLiteOMSStorage()
        return oms.get_object_type(entity_type) is not None

    def validate_properties(self, entity_type: str, properties: Dict) -> List[str]:
        type_def = oms.get_object_type(entity_type)
        errors = []
        for prop_def in type_def.properties:
            if prop_def.required and prop_def.name not in properties:
                errors.append(f"Missing required property: {prop_def.name}")
            # 类型检查...
        return errors
```

### 修正 2：统一 OntologyDocument 定义

废弃 `models/ontology_engine.py` 中的简化版 OntologyDocument，统一使用 `schema/document.py` 的完整版。管理引擎内部需要完整字段时，直接引用 schema 版本。

### 修正 3：Domain 模型降级为种子数据源

将 `schema/domain.py` 的 ENTITY_TYPES 降级为 OMS 的种子数据源（仅首次初始化时使用），运行时类型查询统一走 OMS。移除 `import_ontology()` / `export_ontology()` 中的 `global` 修改。

### 修正 4：LinkDefinition 基数校验

在 QueryService 的 TopoSource 中实现基数校验：

```python
class TopoSourceImpl:
    def validate_cardinality(self, source_type: str, target_type: str, link_name: str,
                              current_count: int) -> bool:
        link_def = oms.get_link_definition(source_type, link_name)
        if link_def.cardinality == "one_to_one" and current_count >= 1:
            return False
        # ... 其他基数检查
        return True
```

### 修正 5：ActionType OPA 集成

在 ActionService 执行动作时，根据 ActionTypeDefinition.opa_policy 自动调用 OPA：

```python
class ActionExecutor:
    async def execute_action(self, action: ActionRecord) -> ActionRecord:
        action_def = oms.get_action_type(action.action_type_id)
        if action_def.opa_policy:
            opa_result = await opa_manager.check(action_def.opa_policy, {
                "action": action.action_type_id,
                "target": action.target_object_id,
                "user": action.requested_by,
            })
            if not opa_result.allow:
                action.status = "rejected"
                return action
        # ... 执行动作
```

## 后果

**正面**：
- OMS 类型定义从"声明性的"升级为"执行性的"
- 消除两套 OntologyDocument 的维护负担
- Domain 模型与 OMS 的语义重叠问题解决
- LinkDefinition 基数约束生效
- ActionType 的 OPA 策略真正集成

**负面**：
- 读时校验增加查询延迟（可缓存缓解）
- 热写入路径仍为宽松模式（设计权衡，保证实时性）
- Domain 模型降级需要迁移现有数据

## 可逆性
中。类型校验可通过配置开关启用/禁用。OntologyDocument 统一需要代码修改但可分步进行。
