# ADR-054: 规格与架构文档瘦身

## 状态

- 状态：已接受
- 日期：2026-07-08

## 背景

随着 ODAP 平台迭代，`specs/`（spec-kit 生成）与 `docs/`（架构/设计/需求）体量持续膨胀：

- `specs/`：19,565 行 / 61 文件 / 1.2 MB，8 个 spec 目录
- `docs/`：75,571 行 / 206 文件 / 3.4 MB

体量增加主要来自三类"虚重"：**(1) 从未落地的废弃 spec**；**(2) 与源码 100% 重复的内联文档**；**(3) 同一过程的多次快照/派生产物**。这些文档不承载产品功能描述，却显著增加维护与检索成本。

核心约束：**瘦身不得损失任何功能描述**（用户故事、验收标准、API 契约、数据模型本质）。

## 决策

采取"删除死文档 + 精简过程产物 + 保留功能真相源"的策略：

1. **删除确认的死文档**（git 仍追踪，可 `git restore` 恢复）：
   - `specs/002-copilotkit-eval/`（4,922 行）：CopilotKit 全仓零引用，从未实现
   - `specs/006-llm-config-management/`（1,516 行）：功能已由 `odap/biz/platform/config/`（config.db + 热更新）实现并文档化，spec 仍 Draft
   - `specs/004-microservice-split/`（329 行）：微服务拆分未采纳，零引用
   - `specs/ui-ux-pro-max/`（245 行）：早期碎片
   - `docs/02-architecture/ARCHITECTURE_FULL_CHAIN_DEEP.md`（5,210 行）：内联源码（`# odap/...py`），与仓库重复

2. **保留并精简活跃 spec**（`001` 核心 / `003` 本体重构 / `005` 数据采集评估 / `000` 架构评审）：
   - 保留功能真相源：`spec.md`（用户故事+验收）、`contracts/`（API 契约）、`data-model.md`（schema）、`plan.md`/`research.md`（设计依据）
   - 删除派生/次级执行产物：`000` 的 6 份重复评审报告 → 合并为单文件 `SUMMARY.md`；`001` 的 `tasks-review.md`/`tasks-dependency-diagram.md`（明确"从 tasks.md 派生"）；`003` 的 `tasks-us3.md`（US3 子集）

3. **docs/ 去重核验**：除 `FULL_CHAIN_DEEP` 外，其余 `DESIGN.md` 与 AI 助手系列文档（统一设计/独立组件化/平台功能本体/操作手册 Schema/升级报告）均为**单一职责、内容互不重复**的文档，不做批量去重以避免丢失模块级设计细节。

## 后果

**变得更容易：**
- 文档总量下降 14,222 行（约 −15%）；`specs/` 下降 46%，检索与维护成本显著降低
- 消除了"从未实现的功能 spec"与"和源码重复的文档"带来的误导
- 活跃 spec 保留完整功能描述，删减部分均为非功能的执行/评审过程产物

**变得更难 / 注意：**
- 被删 spec 若未来要重启（如 CopilotKit 探索），需从 git history 恢复
- `000` 评审细节从 7 份报告收敛为 1 份 `SUMMARY.md`，极端细粒度任务表被压缩（关键修复结论已保留）
- `docs/` 中 `00-requirements/archive/req-alpha.md`、`req-beta.md`（共 ~3,700 行）为已归档旧需求，由 `req-ok.md` 权威替代；本次未删（归档即有意保留），可作为后续低优先级清理项

## 后续复查与修复（2026-07-08 二次审计）

首轮瘦身后进行了一次规格文档复查，发现并修复了首轮的遗留缺陷：

**发现的残缺（断链）：**
- 删除 `ARCHITECTURE_FULL_CHAIN_DEEP.md` 时未同步清理引用，导致 **21 个文件** 出现指向该已删文件的 markdown 链接死链（涵盖 `ODAP综合优化设计文档.md`、全部 `03-modules/*/DESIGN.md`、`06-dfx/README.md`、多个 `ADR-0xx`、`docs/README.md`、`DOCUMENT_RELATIONSHIP.md` 等）。`ADR-054`（README 标"已接受"）的实现文档亦指向死链。
- `000-architecture-review/` 缺 `spec.md`，不符合 spec 目录结构。

**冗余（非功能过程产物）：**
- `specs/005-data-collection-opt/checklist-review.md`（Superspec Review Report，纯代码修复记录）。

**修复动作（用户确认：重定向到 FULL_CHAIN.md + 全部执行）：**
- **P0 断链修复**：将 21 个文件中的 `ARCHITECTURE_FULL_CHAIN_DEEP.md` 链接批量重定向至现存的 `ARCHITECTURE_FULL_CHAIN.md`（同目录非 DEEP 版架构文档）。git 可恢复。
- **P1 过程产物清理**：删除 `specs/005-data-collection-opt/checklist-review.md`。
- **P2 结构一致性**：为 `000-architecture-review/` 补 `spec.md`，明确"本目录为架构评审记录、非功能规格，详见 SUMMARY.md"。

**复查确认的"健康项"（证明首轮未误伤）：**
- `001` 的 `research/plan/tasks` 对 `spec.md` 的 8 个 User Story、39 处验收标准 **0 处复制**（层间零重述）
- 三份 `quickstart.md`（平台启动 / 本体提取 / 数据采集）内容各异，非模板冗余
- `contracts/` 在 001/003/005 均完整；`data-model.md`（1,796 行）为真实 DB schema，非冗余
- 除 `FULL_CHAIN_DEEP` 外无真断链；spec.md 之间不互引

**经验沉淀（防止复发）：**
- 删除文档时必须同步清理引用（建议纳入删除 checklist / pre-commit 校验），避免"删文件留死链"的系统性残缺。

## 防复发工具与技能固化（2026-07-08 第三轮）

将"删文件 → 必须查引用"这一铁律**工具化**，避免依赖人工记忆：

1. **死链检测脚本** `scripts/check_dangling_doc_links.py`（stdlib only，无需依赖）：
   - 扫描 `docs/` `specs/`（可 `--roots` 扩展），报告指向不存在本地文件的 markdown 链接死链。
   - 兼容项目 `docs/` 为隐式链接根的约定（同时尝试"相对文件 / 相对仓库根 / 相对 docs/ / 相对 specs/"多基准），并跳过外部链接、纯锚点、代码/正则样本，减少误报。
   - 支持 `--ci` 退出码 1，可接入 pre-commit / CI。
2. **可复用技能** `.workbuddy/skills/spec-doc-audit/SKILL.md`：固化"体检 → 删除（可逆优先）→ 引用清理 → 沉淀"四阶段方法论与分类判定速查表。

## 新发现：115 处预存死链（独立于本次删除）

执行第三轮时，检测脚本暴露出 **115 处 markdown 死链**，经抽样核实（`docs/03-modules/permission_checker/`、`web/`、`mock_engine/`、`docs/ARCHITECTURE.md`、`TASK_BREAKDOWN.md`、`ARCHITECTURE_PLAN.md` 等均真实缺失）确认：

- **这些死链均不指向本次删除的文件**（唯一指向已删对象的是 sanguo 文档中已修复的 CopilotKit 提及，现已 0 WARN）。
- 根因是**历史模块改名 / 文件迁移**遗留：`permission_checker/`→`opa_policy/`、`web/`→`web_frontend/`、`mock_engine/`→`simulator`/`event_simulator/`；`docs/ARCHITECTURE.md`→`docs/02-architecture/ARCHITECTURE.md`；`specs/001-odap-platform/contracts/README.md` 列了 21 个**从未创建的**契约文件。
- 与本次瘦身**无关**，属于独立的文档质量债。

**处置执行结果（2026-07-08 第四轮 — 死链大扫除）：**

用 `scripts/check_dangling_doc_links.py` 导出完整 115 处死链清单 → 逐条验证真实目标 → 构建映射 → 经用户确认后执行。结果：**115 → 1**（仅 `mock_engine` 歧义保留待定），全部 git 可恢复、零误映射。

- **Tier 1 自动重定向（84 处，磁盘校验后落盘）**：`adr/`→`07-adr/`（ARCHITECTURE_EVOLVE 33 + 综合优化文档 17 + req-beta）、`permission_checker/`→`opa_policy/`、`web/`→`web_frontend/`、`modules/`→`03-modules/`、`ui/`→`04-ui/`、SCALABLE 的 `../../07-adr/` 少一级 `../`、`00-00-requirements` 笔误、`../ODAP综合优化设计文档` 补 `01-product-design/`、`../../specs` 少一级 `../`、已知安全 ADR 改名（ADR-003/028 旧名→真实文件名）。
- **Tier 2 转纯文本（30 处，用户确认）**：A 组 9 处目标确认已删/从未存在（ARCHITECTURE_VALIDATION_REPORT、ADR-018、ADR-054、ADR-006_agent_链路追踪系统、RESTRUCTURE_PLAN、tools/DEVELOPMENT_GUIDE、TASK_BREAKDOWN、ARCHITECTURE_PLAN×2）→ 删死链保留文字；B 组 `contracts/README.md` 21 个从未创建的契约文件索引 → 链接转纯文本保留文件名。
- **C 组保留待定（1 处）**：`ADR-022:59` 的 `mock_engine/DESIGN.md`——`simulator/` 与 `event_simulator/` 二义，留待人工确认。

新增修复器 `scripts/fix_dangling_doc_links.py`（`--apply` 落盘，每条重写前 `target_exists` 磁盘校验，不存在绝不盲改）与 `scripts/remove_dead_links.py`（无目标死链转纯文本，跳过 `mock_engine`）。两脚本 + 检测脚本构成"查→修→验"闭环。

经验：删除/迁移文档必须同步清理引用；批量改链接前须用检测脚本生成清单并逐条验证目标存在，避免"删文件留尾巴"与"盲映射误伤"。
