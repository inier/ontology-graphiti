## Context

### 现状：有契约无实现

ADR-072 定义了 `ReasoningServiceContract`（+AI Reasoning 层统一推理入口），包含三类能力：

| 契约方法 | 语义 | 现状实现 |
|---|---|---|
| `infer_types()` / `suggest_constraints()` | 推理组（服务 L1 Design） | 散落在 `assistant/rules/`、`design/services/validation/`，无统一引擎 |
| `check_schema_consistency()` / `check_instance_consistency()` | 一致性组（服务 L2 Construction） | `health/` 模块的自定义校验逻辑 |
| `get_reasoning_capabilities()` | 分析组（服务 L3 Application） | 无 |

ADR-072 明确"实现可替换：规则引擎 / LLM-based / 混合模式"，但**确定性推理引擎的实现从未落地**——当前所有推理路径最终都依赖 LLM（`infra/llm/ZhipuAIClient`），带来三个问题：

1. **不可解释**：LLM 推理无法产出结构化的推理路径（哪些规则命中、推导步骤是什么），与 ADR-076 的 `reasoning_trace` 字段和"可审计 100%"目标冲突
2. **不确定**：同一输入多次调用结果可能不一致，不适合合规场景（金融/医疗/法律的目标场景）
3. **成本高**：本可用规则秒级完成的类型推断/约束校验，全部走 LLM 调用

### 外部参照

Semantica 调研（[RESEARCH_SEMANTICA_COMPARISON_2026-08-14](../02-architecture/reports/RESEARCH_SEMANTICA_COMPARISON_2026-08-14.md) §4.3）确认推理引擎是 ODAP 的明显缺口：Semantica 内置前向链接、Rete 网络、Datalog、SPARQL 推理且**推理路径完全可解释**。调研结论为"不引入 semantica 整包，参考其架构在 ADR-068 +Reasoning 层实现确定性推理"。

> ⚠️ **显式声明（2026-08-16 修订）**：**不参考 Semantica 的 Rete 实现**——其官方自认 `match_patterns()` 条件匹配器尚不成熟，生产合规使用前需自行验证。本 ADR 的 pyDatalog/experta 选型不受影响；Semantica 的性能数据（CHANGELOG 历史记录而非 CI 断言）亦不作为选型依据。

### 关键边界：与 OPA 正交

ODAP 已有 OPA（Rego）策略引擎（ADR-003/009/028）。必须显式声明两者正交，避免能力重叠：

| 维度 | OPA (Rego) | 确定性推理引擎 (本 ADR) |
|---|---|---|
| 管什么 | **权限策略**：谁能对什么资源做什么操作 | **业务推理**：从已知事实演绎出什么结论 |
| 输入 | JWT 主体 + 资源 + 环境属性 | 图谱事实（ABox）+ 本体规则（TBox） |
| 输出 | allow/deny 决策 | 推导结论 + 推理路径 |
| 调用点 | API 网关、action 执行前 | Design/Construction/Application 层推理服务 |
| 规则来源 | Rego 策略文件（infra/opa/policies） | 本体定义中的业务规则（随本体版本管理） |

**禁止事项**：推理引擎不做权限判断；OPA 不做业务演绎。两者可在同一请求链路中先后调用（如：推理得出建议动作 → OPA 校验该动作权限），但不互相替代。

### 运行环境约束（已核验）

- 容器 Python 版本：**3.11.15**（`graphiti-dev-app`，2026-08-15 核验）
- 部署方式：Podman 容器（`docker_app:latest` 镜像），新增 pip 依赖需改 `apps/api/pyproject.toml` + `uv.lock` + `bootstep.py rebuild main`
- 与 ADR-076 不同：本 ADR **必然引入新依赖**，镜像重建不可避免

## Decision

### 1. 引擎选型：分主备两级，spike 验证后定案

候选矩阵（针对 Python 3.11 兼容性、维护活跃度、能力匹配度）：

| 候选 | 推理范式 | Python 3.11 兼容 | 维护状态 | 可解释性 | 评估 |
|---|---|---|---|---|---|
| `pyDatalog` | Datalog | ✅ 0.17.4 已实测 3.13 可运行（spike 2026-08-16） | 低活跃 | 好（推导树） | **已定案** |
| `experta` (PyKnow fork) | Rete/前向链接 | ❌ 硬锁 frozendict==1.2（依赖已删除的 collections.Mapping），3.10+ 全线不可用（spike 2026-08-16） | 中 | 好（规则命中轨迹） | **出局** |
| `durable_rules` | Rete | ⚠️ 有原生依赖，容器镜像需加构建工具链 | 低活跃 | 中 | 备选 |
| `clingo` | ASP（回答集编程） | ✅ 官方 wheel | 活跃 | 中 | 能力溢出（ODAP 无需 ASP 全部能力），备选 |
| 自研轻量前向链接 | IF/THEN | ✅ | — | 完全可控 | 兜底方案（规则集小时可行） |

**决策流程**：开工第 1 周执行 spike（容器内 `pip install` 候选库 + 最小规则集验证），按"3.11 兼容性 → rule_trace 可解释输出能力 → 性能"顺序裁决。**默认倾向 pyDatalog**（Datalog 语义与知识图谱事实模型天然同构），兼容性验证失败则降级 `experta`。

**spike 定案（2026-08-16）**：完整数据见 [Spike 验收报告](../02-architecture/reports/spike_engine_2026-08-16/REPORT.md)。结果：**experta 出局**（硬锁 `frozendict==1.2`，Python 3.10+ 全线不可用，uv 解析冲突证实无法覆盖）；**pyDatalog 0.17.4 定案**（3.13 实测可运行，非递归单次推理达标：场景 A 1.9ms / 场景 B 255.4ms P95；rule_trace 构建 < 1ms）。**架构约束（spike 数据强制）**：
1. **目标化查询**：推理 API 一律指定谓词 + 绑定（`query(goal, bindings)`），**禁止无约束全量演绎**（全量 90 谓词 P95=16.1s，物化 147k 结论）
2. **递归治理**：递归规则 ≤ 5 条/本体版本且仅限受限起点调用；无约束递归 500 节点/800 边即超时——超限降级 Neo4j Cypher 可变长度路径（`[r*1..k]`）或自研迭代展开（Considered Options 5）
3. **结论规模上限**：单次推理结论数 ≤ 10k，超出截断并标记 `truncated: true`（与 ADR-076 `reasoning_trace` 兼容）
4. **单规则超时**：500ms（`futures` 包裹执行），命中即走 hybrid 降级（§4 裁决）

### 3. 规则模型与存储

**规则归属本体**：业务规则是本体定义的一部分（TBox 扩展），随本体版本管理（复用 ADR-068 L1 Design 的版本机制），工作空间隔离继承本体隔离。

```python
class BusinessRule(BaseModel):
    rule_id: str
    ontology_id: str              # 所属本体
    workspace_id: str             # 隔离边界（必填，非空校验）
    name: str
    description: str = ""
    rule_text: str                # Datalog 语法规则文本，如:
                                  # "ancestor(X,Z) :- parent(X,Y), ancestor(Y,Z)"
    enabled: bool = True
    priority: int = 0             # 冲突时的优先级
    valid_from: datetime          # 随本体版本生效
    created_by: str
```

存储：SQLite（`odap_business_rules` 表），随本体版本快照。规则文本经**语法校验**（加载时编译，编译失败拒绝入库）+ **安全约束**（仅允许 Datalog 白名单语法，禁止任意 Python 求值）。

#### 3.1 规则安全约束白名单（grilling 裁决 2026-08-16）

规则文本在**加载编译期**与**运行期**双重受控，禁止任意 Python 求值。白名单范围：

| 类别 | 允许 | 拒绝 |
|---|---|---|
| 谓词名 | `[a-z][a-zA-Z0-9_]*`（字母开头） | 双下划线（`__`）、内建函数名（`print`/`eval`/`exec`/`import`/`getattr` 等） |
| 常量 | 字符串字面量、十进制数字、布尔 | 复合表达式、f-string、隐式求值 |
| 变量 | 大写字母开头的标识符（Datalog 惯例 `X`/`Y`/`Z`） | 下划线起始变量名之外的任意标识符引用 |
| 规则语法 | `Head :- Body .`、`,` 合取、`.` 结束、可选括号 | `;` 析取、`not` 裸否定（走安全子句 `not_` 谓词）、递归自引用限制（深度 > 16 拒绝） |
| 内置运算 | 比较（`=`/`!=`/`<`/`>`）、`+`/`-`/`*`（数值） | 除法余数链、位运算、切片、lambda |

实现方式：`rule_loader` 内嵌白名单 tokenizer + 文法解析器（约 200 行，无第三方依赖）；校验失败返回 `RuleValidationError`（含行号/列号/违规 token），**拒绝入库**；运行期以只读内存求值器执行（不反射、不 eval、不 exec）。安全约束属于规则管理服务能力，与 OPA（权限层）职责不重叠。

#### 3.2 规则版本与本体重置/回滚联动语义（grilling 裁决 2026-08-16）

现有 `ConstructionRollbackManager` 支持三级回滚（VERSION/PIPELINE/BATCH，见 `construction/rollback/rollback_manager.py`）。规则作为 TBox 扩展，联动语义：

| 回滚级别 | 规则行为 |
|---|---|
| **版本级**（`rollback_version`，全量重新摄入） | 规则随版本快照整体恢复：回滚目标版本的 `odap_business_rules` 快照被还原，`valid_from` 重写为回滚时点；回滚后该版本的规则集重新可用 |
| **Pipeline 级**（`rollback_pipeline`） | **不触碰规则**：流水线只写 ABox（图谱事实），规则是 TBox，不在流水线步骤内变更 |
| **Batch 级**（`rollback_batch`） | **不触碰规则**：仅删除图谱批次写入 |

补充约束：规则变更只通过"规则管理服务"（随版本提交）发生，禁止在构建流水线步骤中直接改规则表；规则表增加 `version_id` 列（可空），版本回滚时由规则存储负责快照还原（实现为事务内 `DELETE + INSERT`）。

### 4. 推理执行流程与混合策略

```
推理请求（infer_types / check_consistency / ...）
        │
        ▼
fact_loader: Neo4j ABox 按 workspace_id + ontology_id 提取 facts
        │（Cypher → Datalog 事实断言，如 parent("a","b")）
        ▼
rule_loader: 加载该本体版本启用中的规则集
        │
        ▼
确定性引擎演绎（毫秒~秒级，零 LLM）
        │
        ├─ 成功（置信度 ≥ 阈值）→ trace_builder 产出 rule_trace → 返回
        │
        └─ 无结论/置信度 < 0.5 → hybrid 策略降级 LLM 推理
                                   （ADR-072 已规划：规则引擎兜底，
                                    此处反向——确定性优先，LLM 补充）
```

**hybrid 置信度阈值与降级条件（grilling 裁决 2026-08-16）**：

| 判定 | 条件 | 动作 |
|---|---|---|
| **确定性直接返回** | 引擎有结论 且 结论置信度 ≥ `REASONING_CONF_THRESHOLD`（默认 `0.5`） | 返回规则结果，不触发 LLM |
| **降级 LLM 补充** | ①引擎零推导（规则命中为 0）或 ②结论置信度 < `0.5` 或 ③规则执行超时（默认 `500ms`/规则） | 触发 LLM 候选推断，经质量闸后回写（标记 `source=llm_hybrid`） |
| **拒绝服务** | 规则引擎**抛错**（语法/运行时异常，非超时） | 不降级 LLM（防掩盖规则缺陷），返回错误并记录告警 |

补充：阈值 `REASONING_CONF_THRESHOLD` 可配置（环境变量，支持 `0.0~1.0`）；hybrid 模式下一次请求只触发一次 LLM 降级（防风暴），幂等键防重入；降级触发计数写入监控指标 `odap_reasoning_llm_fallback_total`。

**rule_trace 输出格式**（与 ADR-076 `reasoning_trace` 对齐）：

```json
{
  "conclusion": "...",
  "rule_trace": [
    {"step": 1, "rule_id": "r_xxx", "rule_text": "...", "matched_facts": ["..."], "derived_fact": "..."},
    {"step": 2, "...": "..."}
  ],
  "engine": "pyDatalog",
  "duration_ms": 12
}
```

**时态推理扩展（2026-08-16 修订新增）**：`temporal_algebra.py` 实现 Allen 区间代数 13 种关系（before / meets / overlaps / during / starts / finishes / equals 及其逆关系），基于 Graphiti `valid_at`/`invalid_at` 字段推理事实间时态关系（如"事实 A 生效期间事实 B 是否也生效""决策时点哪些事实处于生效态"）。纯 Python 实现（约百行确定性代码），**零新增依赖**，不占用引擎选型的 Python 3.11 兼容性风险预算。

**`state_at()` 落位声明**：任意历史时点的图快照查询（"当时我们看到的是什么"）不属于本 ADR 范围——其本质是 Graphiti `valid_at`/`invalid_at` 过滤器（`SearchFilters` 已含，0.29.2 已核验）的服务层暴露，落 `infra/graph`（GraphManager 增强），作为 Phase 2 工作项实施，不单列 ADR。

### 5. 与现有能力的适配（ADR-072 要求的适配器）

| 现有模块 | 能力 | 适配方式 |
|---|---|---|
| `assistant/rules/` | TypeInferenceRule | 重写为 Datalog 规则集，经 `rule_loader` 加载 |
| `health/` | 一致性校验 | Schema 级规则编译为 Datalog；实例级校验走 `check_instance_consistency` |
| `design/services/validation/` | Schema 校验 | 保留结构校验（格式/必填），语义校验（约束冲突）移交推理引擎 |
| `cognition/` | 意图识别/知识导航 | **不移交**（本质是 LLM 任务，非确定性推理范畴） |

#### 5.1 一致性校验从 `health/` 迁移的能力清单（grilling 裁决 2026-08-16）

`health/` 现有 5 类校验全部纳入确定性引擎能力边界，映射如下（`check_instance_consistency` 为对外保留的统一入口）：

| `health/` 能力 | Datalog 映射 | 迁移状态 |
|---|---|---|
| `not_null`（必填） | 单规则：`inconsistent(X) :- cls(X), not has_attr(X, "_", _)`（安全子句实现） | 迁移 |
| `range`（值域） | 数值比较规则（`age < 0` 等） | 迁移 |
| `regex`（格式） | 语法编译期转正则（Datalog 常量比较 + 白名单正则表） | 迁移 |
| `unique`（唯一性） | 计数聚合（`count(X, N) :- ...`，`N > 1` → 违规） | 迁移 |
| `referential_integrity`（引用完整性） | 跨类型 join 规则（`broken_ref(X) :- ref(X, Y), not exists(Y)`） | 迁移 |

迁移约束：①`health/` 保留 Schema 级结构校验（格式/必填字段），仅语义校验移交；②迁移后提供**对拍测试**（新旧结果逐项比对，覆盖 5 类能力样本）；③`/health` 接口保持兼容（内部转发到 `check_instance_consistency`），不允许前端感知差异。

### 6. 与 ADR-076 的协同

- 决策推理阶段（`decision_pipeline._decide`）可调用推理引擎增强 `_decide`，`rule_trace` 直接写入 `DecisionRecord.reasoning_trace`
- 推理过程审计（ADR-074 审计项 #4"推理过程审计"）由 `trace_builder` 输出承载，经 `save_audit_episode()` 写入 Graphiti（零 LLM）

## Consequences

### 变得更容易

- 推理路径完全可解释（rule_trace），支撑 ADR-076 决策追溯和 ADR-074 推理审计
- 类型推断/约束校验/一致性检查从 LLM 调用（秒级、有成本）降为本地演绎（毫秒级、零成本）
- 合规场景获得确定性推理能力（可重现、可审计）
- ADR-072 契约从"纸面契约"变为有实现支撑

### 变得困难/需注意

- **新依赖引入**：需改 `pyproject.toml` + 重建镜像（`bootstep.py rebuild main`），与 ADR-076 的零依赖不同
- **规则编写门槛**：Datalog 语法对业务人员有学习成本——缓解：L6 前端提供规则模板和可视化编辑器（列入 Phase 2 范围外，后续迭代）
- **双引擎协调**：确定性 vs LLM 的边界需运营调优（置信度阈值）——缓解：hybrid 策略配置化
- **pyDatalog 兼容性风险已解除**：0.17.4 在 3.13 实测可运行（spike 2026-08-16）；但**递归/全量演绎性能硬伤**需架构约束兜底（目标化查询 + 递归治理 + 结论上限）。experta 因 frozendict 硬锁出局，**无备选引擎**——回退仅剩自研前向链接器（Considered Options 5），工期风险从"切换库 3-5 天"转为"自研兜底 1-2 周"（仅在递归需求无法被 Cypher/迭代展开覆盖时触发）

## Considered Options

1. **引入 semantica 整包用其 reasoning 模块**——否决（调研报告已决：与 Graphiti/HE 职责重叠，v0.6.5 早期，仅参考架构）。
2. **用 OPA Rego 承担业务推理**——否决：Rego 为策略决策设计，递归演绎/多跳推导表达力弱于 Datalog；且混淆权限与业务两类规则的治理边界。
3. **纯 LLM 推理不建确定性引擎**——否决：不可解释、不确定、成本高，与"可审计 100%"目标冲突。
4. **clingo (ASP) 一步到位**——备选保留：能力最强（支持约束求解），但 ODAP 当前场景（类型推断/一致性/前向演绎）用不到 ASP 的稳定性模型语义，引入成本大于收益。
5. **自研轻量前向链接器**——兜底保留：若 spike 发现所有候选库在 3.11 均有问题，规则集规模小（<100 条）时自研 IF/THEN 链式求值器约 200 行核心代码可覆盖。

## Reversibility

**高**。确定性引擎是 `ReasoningServiceContract` 的一个实现，契约不变；规则数据独立 SQLite 表存储，移除引擎不影响本体数据；`pyproject.toml` 依赖可随模块移除回退。唯一沉没成本是已编写的 Datalog 规则集（可导出为文本保留）。
