# ADR-095: 意图识别分层方案与泛化度量

## Status

**已接受（2026-10-17）**。本轮锁定四级漏斗意图识别方案与离线泛化评测口径。

---

## Background

用户核心需求：问题**意图识别能力强、泛化能力强**；结果正确、完整、可溯源。

**现状（文件:行证据）**：

- 已存在语义路由能力：`biz/core/agent`（ADR-043 `agent_router_semantic_routing`）。
- 已存在 USL 术语表：`biz/semantic_admin/usl_manager`（术语/同义词管理的天然数据源）。
- 已存在概念缺口回路：`semantic_admin/gap_pool`（ADR-086），可供「映射不到」时落缺口。
- **缺口**：无统一意图识别管线；无「泛化能力如何度量」的离线评测集与指标。

**约束**：LLM 输出须受本体约束（不得开放式生成后直接执行）；不新造 DSL。

---

## Decision

采用**四级漏斗**（详见架构 v2 §3.1）：

1. **L1 词典/别名匹配**（确定性、零成本）：USL 术语表 + 同义词。
2. **L2 语义路由**：embedding 召回候选 intent（复用 ADR-043 语义路由）。
3. **L3 LLM 消歧**：仅在**受限候选 intent 集**内选择，强制 JSON Schema 输出。
4. **L4 本体槽位填充**：受 TBox 约束的槽位抽取；不可映射 → `gap_pool` → HITL 澄清。

**泛化度量**（离线评测集，落 `apps/api/tests/eval/intent/`）：

- 评测集维度：同义改写（≥200）、跨域迁移（≥100）、复合意图（≥100）、干扰项（≥100）。
- 指标：`Intent-Acc@1`（目标 ≥0.90）、`Slot-F1`（目标 ≥0.85）、`Gen-Gap`（跨域与内置集 Acc 差，目标 ≤0.10）、`Clarify-Rate`、`Unmapped-Rate`。
- 门禁：指标进 CI 回归集，跌破基线即拦截合并。

**原则**：宁澄清不猜（低置信返回澄清问句）；映射不到进缺口回路，不静默丢弃。

---

## Consequences

**正面**：
- 分级漏斗逐级降本（L1/L2 命中免 LLM 调用），成本与延迟可控。
- 泛化从「感觉」变「可度量」，`Gen-Gap` 直接驱动本体补全。
- 与编排层输入侧约束、缺口回路无缝衔接。

**负面**：
- 评测集建设与维护有成本（Phase 2 需 ≥500 条标注样本）。
- L3 受限候选集需随本体演进维护，否则召回不足。
- 澄清率上升可能影响体验（以准确换交互轮次）。

## 实现对齐记录（2026-10-17，项目总监裁定）

**问题**：第 2 条写「L2 语义路由：embedding 召回候选 intent」，但实现交付的 L2 是
**确定性构词/动词组合召回**（+ 可选向量补位）。若不作说明，后续维护者会误以为
「必须接入向量服务才能满足 AC-34」，从而在无向量服务的环境里判定本方案不可行。

**裁定：保留原决策，补记实现事实。** 第 2 条的**决策意图**（L2 承担「超出词典字面匹配的
语义召回」这一职责）未变，变的只是**实现手段**。理由如下，均经实测：

| 事项 | 事实 |
|------|------|
| 本机缺依赖 | `sentence_transformers` / `sklearn` / `jieba` / `pypinyin` 均未安装，本地句向量与拼音路径不可用 |
| 向量端点 | OpenAI 兼容端点 `/v1/embeddings` 可用（768 维，nomic-embed-text-v1.5） |
| 对话模型 | `qwen3.8-27b@*` / `master` / `minimax-h3` 均 HTTP 400「Failed to load model」→ **L3 正向路径在本机不可用** |
| L2 实际构成 | ① 中文业务名词后缀的构词形态召回（三道防误报闸门）；② 动词+对象组合召回；③ 字符二元组模糊召回（错别字兜底）；④ 向量召回（默认关闭，仅在前三者均未命中时补位，失败返回空并记 `degraded_reason`，不伪造相似度） |
| 达标是否依赖向量 | **否**。`--layer l2`（关掉 L3 与向量）即达 Acc@1 1.0000 / Slot-F1 1.0000 / Gen-Gap 0.0000 |

**顺带修复的默认装配缺陷（值得记入决策）**：配置层给 `llm.api_base` / `llm.model` 写了内置默认值
（`https://api.openai.com/v1`、`gpt-4`），导致「只看这两项是否为配置项」的判定永远为真——
即便用户从未配置模型，每次低置信查询也会真的外连，8s 超时。现已改为
`api_base + model + api_key` 三者齐备才启用（fail-closed），并有测试锁定。
这是**默认值即配置**的典型陷阱：用「非空」判断「已配置」，在有内置默认值的配置系统里恒为真。

**未解决并如实登记**（不当作已解决）：

1. L3 正向路径仅由注入式 fake client 覆盖（候选封闭/越界/空理由/不可用四类均有断言），
   生产模型输出稳定性**未验证**——本机无可用 chat 模型是硬约束。
2. 主评测集（540 条）与留出集（59 条）已达 **100% 饱和**。饱和意味着该集**不再具备区分能力**，
   无法再发现 L2 层面的残余缺陷；且留出集由实现方自撰，1.0 是「自撰集上的达标」，
   不等于真实用户口语上的泛化。真实泛化仍待线上样本验证。
3. `Clarify-Rate 0.2037` 恰等于干扰项占比（110/540），即澄清**全部**发生在干扰项上、
   且干扰项**全部**正确澄清；但这也说明「真实用户模糊提问该不该澄清」这一路径未被评测覆盖。
4. 后缀表与业务动词白名单是供应链/电商领域白名单，换垂直行业需扩表——属词表运营，
   建议接入 `gap_pool` 做数据驱动扩张（当前 `Unmapped-Rate = 0`，仅说明本域内无漏网术语）。
