# ADR-062: 知识图谱读写分离与冷热分层

## 状态
Accepted

## 上下文

ODAP 以 Graphiti 双时态知识图谱（ADR-002）为核心，当前运行在 **Neo4j 社区版单数据库**（ADR-041 标签过滤隔离），承担三类负载混跑：

1. **写入**：文档摄入、Agent 回写、双时态实体/边构建。
2. **推理/检索**：RAG 检索、双时态历史回溯、语义检索（Semantic Retriever）。
3. **分析**：态势查询、可视化遍历。

随着图谱节点/边规模增长（目标百万级），单实例出现：写入锁竞争、双时态推理成本高、RAG 检索延迟上升、全量备份窗口拉长。社区版无因果集群/多库能力，分片（Fabric）需企业版与专职 SRE。

约束：6–12 月内团队仍 3–5 人、无专职 SRE，不得引入企业版强依赖。

## 决策

采用 **分阶段的数据层扩展**，而非一步到位分片：

1. **近（Q1–Q2）CQRS 读写分离 + 向量 offload**：
   - 写入走 Neo4j 主库；问答/检索类读请求导向**只读副本**或只读视图。
   - Embedding 向量检索从 Neo4j 抽离到**专用向量库**（Milvus / Qdrant），复用现有 SiliconFlow `bge-m3` Embedder 的 embedding 通道，仅变更检索后端。
   - 引入查询缓存层（命中高频问答/态势查询）。
2. **中（Q2–Q3）冷热分层**：
   - 活跃实体/近期时序保留在 Neo4j **热库**；历史双时态快照下沉**冷存**（对象存储 + 列存，如 Parquet + DuckDB）。
   - 访问层（`IGraphitiClient`）抽象冷热路由，调用方无感。
3. **推迟（Phase 5+）图谱分片**：待"单实例成瓶颈 + 有专职 SRE + 企业版预算"三条件同时满足再评估 Fabric/多集群。

### 拓扑

```
Write Primary (Neo4j)  ──复制──>  Read Replica (只读)
        │
        ├─> Vector Store (Milvus/Qdrant)   # 向量检索 offload
        └─> Cold Store (对象存储+列存)       # 历史时序快照
```

## 后果

### 变得更容易
- 写入吞吐不被读查询拖垮，RAG 检索延迟下降（向量库专用索引）。
- 热库体积可控，备份窗口缩短；历史回溯仍可查冷存。
- 不依赖企业版即可获得显著扩展收益。

### 变得更难
- **复制延迟**：读副本存在陈旧窗口，必须显式定义可接受陈旧度 SLA（如问答允许 ≤ N 秒陈旧，强一致写后读走主库）。
- 组件增多：向量库、冷存、缓存需运维与监控（由 ADR-064 覆盖）。
- 冷热跨查需访问层正确路由，逻辑变复杂。

## 可逆性
**高**。读写分离可回退为单库（关闭副本路由）；向量 offload 可回退为 Neo4j 内检索；冷热分层可先以"全热"运行、后续再下沉。
