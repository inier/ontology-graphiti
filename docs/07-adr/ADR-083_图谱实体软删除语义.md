# ADR-083: 图谱实体软删除语义（invalid_at 失效 + 级联边失效 + 读侧过滤）

## Status
**已接受（2026-09-29，实现已落地：#13a Task 1-8 提交完成）**

> 设计依据（spec）：[docs/superpowers/specs/2026-09-28-soft-delete-entity-design.md](../superpowers/specs/2026-09-28-soft-delete-entity-design.md)
> 关联：#13b（批次删除回滚链，独立 spec，依赖本决策的软删能力）；ADR-080 Stage J（本决策前身之一：`GraphWriteProxy.delete_entity` 曾作为「合规通道 100% 失败」断链被登记）

## Context

ODAP 基于 Graphiti 构建双时态知识图谱。在本决策之前，**图谱实体删除能力在全栈所有层均为零**：

- `GraphManager`（`apps/api/odap/infra/graph/`）无任何实体级删除方法；唯一硬删是全量 `clear_graph()` 的 `MATCH (n) DETACH DELETE n`。
- `GraphWriteProxy.delete_entity`（`apps/api/odap/infra/query/graph_write_proxy.py`）是显式报错占位，恒返回 `status="error"`——行动闭环的删除路径（action_service executor、ontology chat execution_tool）因此全部恒失败。
- 双时态只有**读侧**（`query_temporal`/`state_at`），写侧不打任何失效时间戳；节点零时间戳属性。
- 读侧完全不过滤失效实体：~10 处 Neo4j 读路径 + 5 处 fallback 读路径 + 时态索引全部照旧返回，软删要生效必须逐条加过滤，无统一收敛点。

同时，双时态 KG 的定位要求**保留历史**：实体"被删除"在业务上是一个时刻发生的事实（此后不再有效），而非历史上从未存在。硬删会摧毁 as-of 回溯能力。

## Decision

**软删除为默认且唯一的业务删除语义**，不开放硬删业务通道。要点：

### 1. 标记约定：`invalid_at`（ISO-8601 UTC 字符串）

- 节点与关系边统一打 `invalid_at` 属性标记失效时刻；缺失或空 = 活跃，非空 = 已软删。
- 统一存 ISO-8601 字符串（非 Neo4j 原生 temporal），规避 `add_entity`（`_sanitize_neo4j_properties` 转字符串）与 `update_entity`（不清洗、落原生 temporal）之间的写侧类型分裂。
- 判定"活跃"的唯一谓词：`invalid_at IS NULL`（Neo4j）/ `not props.get("invalid_at")`（Python/fallback）。
- 注意区分：graphiti 原生 `valid_at/invalid_at/expired_at` 在 EntityEdge 上；本决策的节点级 `invalid_at` 是应用层自定约定，同名不同物。

### 2. 共享谓词单一真源：`_soft_delete.py`

新建 `apps/api/odap/infra/graph/_soft_delete.py`（infra/graph 模块内私有），导出 `ACTIVE_NODE_PREDICATE` / `ACTIVE_REL_PREDICATE` / `is_active(props)` / `now_iso()`。~15 处读路径（entity_ops / search_ops / relationship_ops / cache_mixin / temporal_ops）全部引用该真源，语义将来只改一处。

### 3. `GraphManager.delete_entity` 接口契约

```python
def delete_entity(entity_id, workspace_id="", cascade=True, actor="") -> Dict[str, Any]
```

- 成功：`{"status":"success","entity_id":str,"entities_invalidated":int,"relations_invalidated":int,"invalid_at":str}`
- 失败：`{"status":"error","message":str}`（not_found、workspace 不匹配、driver 不可用、Cypher 异常均显式 error，规则 2/14，不静默）
- 幂等：对已失效实体再次删除 = success no-op（`entities_invalidated=0`），非 error。
- **级联失效**：`cascade=True`（默认）同步对所有关联边打 `invalid_at`（Neo4j 用无向匹配 `-[r]-()`，等价 in+out 并集；fallback 用 `in_edges + out_edges` 并集，`is_active` guard 保自环幂等；均仅对 `invalid_at` 为空的边写），保持图一致、无悬空边。
- 写后显式 `invalidate_cache()`（否则 300s TTL 内读路径仍返回失效实体）；经 `graph_audit` 落结构化审计（与既有写操作一致）。

### 4. 读路径默认排除失效实体

- 全部读路径（get/query/search/hybrid/RAG/neighbors/traverse/relations/统计）默认过滤失效节点与失效边；`get_entity(include_deleted=False)` 提供 opt-in 查看已删实体。
- 时态 as-of 语义修正：`state_at(vt)` = `valid_time <= vt < invalid_at`——在既有 `valid_time <= vt` 下界基础上追加 `invalid_at` 上界，失效时刻之后不再计入。

### 5. `GraphWriteProxy` 为唯一合规删除通道

`GraphWriteProxy.delete_entity` 去掉墓碑 error-return，透传 `GraphManager.delete_entity` 真实结果并保留 `_log_write` 文本日志；结构化审计由 GraphManager 层 `graph_audit` 负责（避免双层重复审计）。业务侧禁止绕 proxy 拿裸 GraphManager 删除（`get_raw_graph_manager` 墓碑维持 `NotImplementedError`）。

### 6. 调用方接通

- **action_service executor**（`executor.py` delete/remove 分支，唯一生产调用点）：代码不变——proxy 转真实成功后 `_write_failure` 自然返回 None，`success=True`；既有 `test_delete_failure_reports_not_deleted` 继续守护"proxy 报 error 时不得假成功"。
- **execution_tool**（ontology chat 工具）：`delete_entity` 分支从返回 `unsupported` 改为经 GraphWriteProxy 调软删，透传结果。

## Consequences

**正向**：
- 保留双时态历史：删除是"某时刻起失效"的事实，`state_at` as-of 可正确回溯失效前状态。
- 图一致：级联失效关系边，无悬空边。
- 删除可审计：GraphManager 层 `graph_audit` 结构化审计 + proxy `_log_write`，合规通道全程可观测。
- 行动闭环删除路径打通：唯一生产调用点 action_service executor 的 delete 分支由恒失败变为真实软删成败透传；execution_tool 的 `delete_entity` 动作由 `unsupported` 变为可用。
- 活跃谓词收敛到 `_soft_delete.py` 单一真源，将来语义调整只改一处。

**负向 / 已知边界**：
- ~15 处读路径需持续维护活跃谓词（新增读路径必须引用共享常量，否则失效实体会漏出）——已收敛到 `_soft_delete.py`，并由 fallback 真实测试 + Neo4j Cypher 断言测试守护。
- Graphiti 向量检索（EntityEdge fact 层，`search_hybrid`/`_search_graphiti`）**不联动**节点级软删：软删节点后，历史 episode/edge 向量检索仍可能命中其 fact。这属双时态"事实曾成立"语义，是已知边界而非缺陷。
- `delete_by_batch` / 批次回滚链不在本决策内（→ #13b）。
- execution_tool 的 add/update 仍走裸 GraphManager（绕 proxy/审计），是独立既有问题，本次不动（潜在归 #23）。

## Alternatives

- **硬删除**（DETACH DELETE 节点及边）：否决——摧毁双时态历史，不可逆，as-of 回溯能力归零，与 Graphiti 定位冲突。
- **`:Deleted` 标签标记**：否决——标签只表达"已删"布尔态，丢失失效时刻，`state_at` as-of 无法回答"vt 时刻该实体是否仍有效"，时态语义不完整。

## Reversibility

**中**。逆转方式：读路径去掉 `_soft_delete` 谓词引用即回到"不过滤"现状；`delete_entity` 停止调用即回到"显式失败"占位。已打标的 `invalid_at` 属性可通过一次性 Cypher `REMOVE n.invalid_at` 清理，不破坏既有数据 schema（无迁移、无新表、无索引变更）。
