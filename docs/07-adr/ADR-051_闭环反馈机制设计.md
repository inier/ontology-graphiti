# ADR-051: OADP 闭环反馈机制设计

## 状态

提议

## 上下文

OADP（感知-理解-决策-执行）闭环的核心是**执行结果反馈到感知层**，形成持续改进的闭环。当前架构设计中，执行层（Perform）完成后缺少显式的反馈机制，导致：

1. **决策质量无法量化评估** — 决策推荐后无法跟踪实际执行效果
2. **学习机制缺失** — 历史决策的效果无法用于优化未来决策
3. **知识图谱更新滞后** — 新的经验和教训无法及时沉淀

根据 ADR-050 的分析，执行层（Perform）是当前 OADP 闭环的主要缺口，需要设计闭环反馈机制。

## 决策

### 核心设计

实现**三层闭环反馈机制**：

### 反馈类型

| 反馈类型 | 来源 | 内容 | 用途 |
|----------|------|------|------|
| `action_result` | 执行层 | 动作执行结果 | 评估决策有效性 |
| `decision_feedback` | 用户/系统 | 决策采纳情况 | 优化推荐算法 |
| `outcome_deviation` | 分析器 | 预期vs实际偏差 | 调整模型参数 |
| `lesson_learned` | 用户 | 经验教训 | 知识沉淀 |

### 核心接口

```python
# odap/biz/feedback/collector.py
class FeedbackType(str, Enum):
    ACTION_RESULT = "action_result"
    DECISION_FEEDBACK = "decision_feedback"
    OUTCOME_DEVIATION = "outcome_deviation"
    LESSON_LEARNED = "lesson_learned"


class ActionFeedback(BaseModel):
    """动作执行反馈"""
    action_id: str
    decision_id: Optional[str]
    executed_at: datetime
    duration_ms: float
    outcome: str  # success, failure, partial
    result_data: Dict[str, Any]
    error_message: Optional[str]


class FeedbackCollector:
    """反馈收集器 - 收集执行层产出的各类反馈"""
    async def collect(self, feedback: ActionFeedback) -> str: ...
    async def query_feedback(self, decision_id: str, limit: int = 10) -> List[ActionFeedback]: ...


class FeedbackAnalyzer:
    """反馈分析器 - 分析反馈数据，识别模式和偏差"""
    async def analyze_deviation(self, feedback: ActionFeedback, expected_outcome: Dict[str, Any]) -> Dict[str, Any]: ...
    async def identify_patterns(self, feedback_history: List[ActionFeedback]) -> Dict[str, Any]: ...


class FeedbackAggregator:
    """反馈聚合器 - 将分析结果聚合并更新知识图谱"""
    async def aggregate_and_update(self, decision_id: str, analysis_result: Dict[str, Any]) -> bool: ...


class FeedbackLoop:
    """反馈闭环管理器 - 协调反馈收集、分析、聚合的完整流程"""
    async def close_loop(self, action_feedback: ActionFeedback, expected_outcome: Optional[Dict[str, Any]] = None) -> Dict[str, Any]: ...
```

### 知识图谱更新策略

| 反馈类型 | 图谱操作 | 关系 |
|----------|----------|------|
| action_result | 创建 Event 节点 | `:CAUSED -> Decision` |
| outcome_deviation | 更新 Decision 属性 | `:HAS_DEVIATION` |
| lesson_learned | 创建 Fact 节点 | `:INFORMS -> Decision` |

### 实现说明

基于 OpenHarness 实现，FeedbackLoop 包装 DomainSwarm 的 Propagate 阶段，通过 OpenHarness Hook 机制完成反馈闭环。

## 后果

**正面**：
- 决策质量可量化 — 通过反馈追踪，评估决策推荐的有效性
- 持续学习能力 — 历史反馈用于优化未来决策
- 知识沉淀自动化 — 经验教训自动写入知识图谱
- 问题根因追溯 — 偏差分析帮助定位问题根源

**负面**：
- 引入新模块 — 增加系统复杂度（反馈收集、分析、聚合）
- 延迟感知更新 — 反馈处理需要时间，感知更新非实时
- 反馈质量依赖 — 反馈数据质量直接影响学习效果

## 可逆性

中。反馈机制为增量添加，不影响现有 OADP 主流程。如需移除，可禁用 FeedbackLoop 而不影响核心功能。
