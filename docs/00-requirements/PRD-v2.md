## 1. 问题陈述

**谁**：企业内三类角色 —— 本体建模者、业务分析决策者、平台管理员。

**在什么场景下**：企业已有大量结构化（系统表、指标）与非结构化（文档、新闻）数据，希望用「本体」把业务语义统一起来，支撑跨系统归因、智能问数与辅助决策。

**遇到什么痛点**：
1. 业务人员问 AI「这笔订单为什么晚了三天」，AI 能查到数据却**答不对**——语义未对齐、口径不统一、缺乏本体约束（见评估报告 4.2）。
2. 平台建设者面对 **60+ 路由、26 模块、7 套图表栈、259 篇文档**，无法判断「哪条路径是对的、哪份文档是有效的」，**认知负荷过载**（评估报告问题 1/5/6）。
3. 问答结果**无法闭环**：AI 给了分析，但不会提示「你接下来应该做什么」，也无法说明「依据了哪条规则」（评估报告 4.5/4.4）。
4. 历史建设留下**同名多份实现、死代码、重复 API**，改动一处不知另一处是否受影响（评估报告问题 4/8/3.3）。

**现在怎么解决的**：靠人工记忆 + 分散文档 + 口口相传。

**为什么不行**：平台规模已越过「靠记忆可维护」的临界点，**缺收敛导致边际成本递增**——每加一个功能，理解成本、维护成本、出错概率都非线性上升。

## 2. 产品定义

**ODAP（Ontology-Driven Analysis & Decision Platform）** 是一款**本体驱动分析决策平台**：以「本体 = TBox（结构层）+ ABox（实例层）」为唯一业务载体，通过四步法（建本体 / 见本体 / 演本体 / 用本体）把原始数据转化为**语义一致、可推理、可决策、可执行**的资产，并以 USL（统一语义层）为横向能力贯穿全程。

**一句话价值主张**：让企业数据在**本体约束**下被理解、被推理、被决策、被执行——不是「再多一个 BI」，而是「业务世界的可执行语义底座」。

**与竞品本质差异**：多数竞品止步于「语义层 + NL2SQL」（回答"是什么"），ODAP 定位在**决策与执行层**（回答"该怎么办、该由谁办、办完是否合规"），并对**输入与输出双向施加本体约束**。

### 5.2 替代方案

| 方案 | 核心功能 | 优势 | 劣势 / 空白 | 定价 |
|---|---|---|---|---|
| **Stardog / TopBraid EDG**（传统企业知识图谱/本体工程） | RDF/OWL/SPARQL + SHACL 推理与治理 | W3C 标准、推理能力强、模块化 | 学习曲线陡、UI 陈旧、需语义专家；**擅长"建"不擅长"演"**；Stardog 免费版限 1M 边、企业版高价 | Stardog Free / 企业 custom；TopBraid custom |
| **EvoOntology**（开源自进化本体层，人大 ruc-datalab，MIT） | MCP 服务化本体 + 配对评估门自动演化 | 零第三方依赖；DDR-Bench 平均 +17.8；「静态本体塞 prompt 反而变笨」的实证 | 仅支持 Claude Code/Codex；不支持多模态抽取；**每种模型长出的本体不同（迁移掉分 6.6-10.9）**，成本随模型数线性涨；τ 门限未在代码中实现 | 开源免费 |
| **传统 BI + NL2SQL**（Quick BI / FineBI 智问 / 火山 Data Agent） | 自然语言转 SQL 问数 | 开箱即用、部署快、成本低 | 准确率 60-70%；多表 join 弱；**复杂/长尾问题后期维护成本剧烈放大**；无本体约束、无溯源、不会「提醒下一步」 | 按席位/用量，低 |

### 5.3 我们的差异化（为什么选 ODAP 而不是竞品）

1. **决策与执行闭环**：竞品（Snowflake/Databricks/传统 BI）止步于「问答」，Palantir 有 Action 但成本与门槛极高。ODAP 把「决策」作为一等公民对象（ADR-076），原生支持「分析 → 建议 → 执行提醒」闭环。
2. **输入输出双向本体约束**：多数竞品只约束「检索用哪些定义」，不约束「输出是否合规」。ODAP 以 SHACL + 写路径不变量对输入输出双向加约束，这是「不臆造、可审计」的根。
3. **可负担的本体路径**：Palantir 需 FDE 高成本陪跑；ODAP 走「AI 辅助建模（Hyper-Extract）+ 人机审核（候选态）」路线，降低建模门槛。
4. **文档治理与产品内 Wiki 双向打通**：这是 Palantir/Stardog 均未解决的「设计资产失控」问题，ODAP 用 LLM Wiki 一并解决。
5. **可演进而非一次性**：借鉴 EvoOntology「本体即状态」的思路，但避免其「图随模型走」的锁定风险，坚持**模型无关的本体资产 + 配对评估门控**。

## 7. 分批交付顺序与验收标准

> 用户要求「全量一次性推进」，此处给出**推进节奏**而非删减范围：三批并行立项、顺序交付，每批有独立验收门。

### Batch 1（地基批）：收敛 + LLM Wiki —— 目标 4-6 周

**交付内容**：F5（LLM Wiki 模块）、F3（文档治理后端）、F1（统一导航）、F8（重复实现归并）

**验收标准（Given/When/Then）**
- Given 已存在的 259 篇 `docs/**/*.md`，When 运行文档治理流程，Then 每篇文档具备 `owner/role/status/version/supersedes/trace` 元数据，且被分类到 12 个 SDD 层之一，产出《文档归集映射表》。
- Given 存在 10 篇 `ARCHITECTURE_*.md` 与 5 篇评审报告，When 完成治理，Then 存在**唯一** `ARCHITECTURE.md`（status=正式），其余标 `superseded` 并指向新版本。
- Given 用户在任一页面，When 通过主导航查找「Agent / 知识库 / 策略」，Then **各只存在一个入口**，且点击后到达正确页面（无 404、无空页）。
- Given 历史上 `/semantic-admin/pipeline` 与 `/pipeline-runs`，When 交付后，Then 仅保留一条路由，另一条返回 301/重定向，且《迁移映射表》记录旧→新路径。
- Given `config/pages/PolicyManagement.tsx`、`PolicyManager.tsx` 无路由引用，When 交付后，Then 两文件已删除或归档，且《溯源证据》记录删除依据（Grep 证明零引用）。
- Given LLM Wiki 模块上线，When 管理员按角色筛选文档，Then 可看到「该角色应交付的设计文档集」，且文档内容与仓库 md 双向可追溯。

### Batch 2（智能批）：问答闭环 + 合规 + 渲染收敛 —— 目标 6-8 周

**交付内容**：F6a（意图识别）、F6c（溯源）、F6b（执行提醒）、F7（主题重构）、F4（渲染栈收敛）

**验收标准**
- Given 用户输入一句自然语言问题，When 提交，Then 系统在 **2s 内**返回意图分类（chain/nl/mdl/graph/metric/hybrid）与置信度；若置信度低于门限，Then 反问澄清而非猜测。
- Given 用户问「上月华东区退货率为何上升」，When 返回答案，Then 答案附**溯源面板**（依据的本体规则 + 数据源 + 时间范围）。
- Given 得到分析结论，When 结论指向可执行动作，Then 系统给出**建议方案 + 执行提醒**（含责任人/时限），且用户可一键跳转决策记录。
- Given `colorThemeUtils.ts` 存在 `linear-gradient(135deg, #7C3AED 0%, #D946EF 100%)`，When 交付后，Then 该渐变**已移除**，Grep 全前端无紫→品红渐变；主题切换在 ≥3 套风格间可切换且偏好持久化。
- Given 7 套图谱渲染栈，When 交付后，Then 收敛至 ≤2 套，`@ant-design/graphs` 等死依赖**已从 package.json 移除**，构建包体积下降。

### Batch 3（深化批）：本体约束双向 + 契约对账 —— 目标 6-8 周

**交付内容**：F2（本体约束双向）、F9（契约对账）、F10（双时态可见性）

**验收标准**

## 10. 数据埋点方案

MVP 必须埋点的关键事件（不埋 = 上线后无法验证产品假设）：

| 事件类别 | 必埋事件 | 说明 |
|---|---|---|
| 获客 | `page_view`, `sign_up_complete` | 新用户来源、注册转化率 |
| 激活 | `ontology_model_created`（创建第一个本体）、`wiki_doc_indexed`（首篇文档入 Wiki） | 用户完成第一个核心操作 |
| 留存 | `session_start`, `session_duration`, `qa_session_start` | DAU/MAU、问答使用频次 |
| 转化 | `candidate_published`（候选发布为本体）、`decision_executed`（执行决策） | 核心价值转化漏斗 |
| **关键质量** | `qa_intent_confidence`, `qa_answer_has_citation`, **`qa_answer_unmodeled`（未建模兜底触发）**, **`qa_answer_out_of_ontology_blocked`（本体约束拦截）** | 验证「意图识别 + 溯源 + 双向约束」是否真的生效 |
| 异常 | `error_occurred`, `graph_task_failed`（图谱任务真实失败，非伪造 completed） | 前端 + API 错误 |

### 埋点实现要求
- 前端用轻量 SDK（自建 `trackEvent()` 封装或 Umami / Mixpanel）。
- 事件命名规范：`{对象}_{动作}`（如 `ontology_model_created`、`qa_answer_out_of_ontology_blocked`）。
- 属性规范：每个事件附带 `user_id`, `timestamp`, `device`, `version`, `workspace_id`。
- **不采集隐私数据**：不上报 IP、不存原始输入全文（仅存问题哈希 + 意图分类结果）。

## 11. 验收标准（Given/When/Then 汇总）

> 覆盖各功能的核心成功流 + 一条关键错误/边界流。

- **F5 LLM Wiki**
  - Given 管理员登录，When 打开 LLM Wiki，Then 可按「角色 / 文档状态 / SDD 层」三维筛选，且列表显示元数据完整性。
  - Given 某文档缺少 owner 元数据，When 进入文档详情，Then 显示「元数据待补齐」告警。
- **F3 文档治理**
  - Given 存在 ADR-061 双份，When 治理完成，Then 其中一份重编号并记录变更日志，无编号冲突。
  - Given `DOCUMENT_BASELINE` 声称 ADR 54 篇，When 治理完成，Then 基线文档与实际一致（自动校验）。
- **F1 统一导航**
  - Given 用户点击「Agent」，When 导航展开，Then 仅一个 Agent 入口且指向职责明确的页面。
  - Given 访问旧路由 `/policies`，When 请求，Then 自动重定向到 `/policy-editor` 且记录一次 `_redirect` 埋点。
- **F8 重复实现归并**
  - Given `audit/components/AuditTimeline.tsx` 与页面版并存，When 归并完成，Then 仅保留页面版，且无 import 断链（构建通过）。
- **F6a 意图识别**
  - Given 输入模糊问题「那个怎么样了」，When 提交，Then 系统反问澄清而非猜测（`qa_intent_confidence` 低于门限）。
- **F6c 溯源**
  - Given 问答返回结论，When 展开溯源，Then 显示依据的本体规则 ID + 数据源 + 数据时间范围。
- **F6b 执行提醒**
  - Given 结论指向「需补货」，When 生成建议，Then 给出建议方案 + 责任人 + 时限，并可跳转决策记录。
- **F7 主题**
  - Given 用户切换主题，When 刷新页面，Then 偏好保持；且无任何紫→品红渐变（自动化样式检测通过）。
- **F4 渲染收敛**
  - Given 交付后，When 检查 `package.json`，Then 图谱渲染栈 ≤2 套且无零引用依赖。
- **F2 本体约束双向**
  - Given 问题涉及未建模概念，When 回答，Then 明确「未建模」并给建模入口（`qa_answer_unmodeled` 触发）。
  - Given 输出违反本体约束，When 校验，Then 拦截并说明原因（`qa_answer_out_of_ontology_blocked` 触发）。
- **F9 契约对账**
  - Given 67 条前端路由，When 对账完成，Then 每条路由均有后端支撑或已标注为「静态页 / 已知缺口」。
- **F10 双时态可见性**
  - Given 推演数据，When 业务人员查询，Then 默认不可见。

## 12. 边界条件

- **空状态**：无本体时，问答页给出「先建本体」引导 + 示例；Wiki 无文档时给出导入引导。
- **错误状态**：后端/Celery 不可用时**显式报错**（禁止静默伪造 completed），提供重试与降级说明。
- **加载状态**：AI 生成中显示进度 + 中止按钮 + 预计剩余时间。
- **边界值**：单文档超大（>50MB）拒绝并提示；节点数超阈值时图谱分批渲染。
- **并发**：多人同时编辑同一本体节点时加锁（复用 `ws/edit_lock_handler.py`）。
- **离线**：网络中断时保留草稿，恢复后提示同步。
- **权限拒绝**：候选态对业务人员不可见；越权访问返回明确提示而非空白页。
