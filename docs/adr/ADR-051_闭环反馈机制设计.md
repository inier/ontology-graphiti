# ADR-051: OADP 闭环反馈机制设计

## 状态

提议

## 上下文

### 问题背景

OADP（感知-理解-决策-执行）闭环的核心是**执行结果反馈到感知层**，形成持续改进的闭环。当前架构设计中，执行层（Perform）完成后缺少显式的反馈机制，导致：

1. **决策质量无法量化评估** - 决策推荐后无法跟踪实际执行效果
2. **学习机制缺失** - 历史决策的效果无法用于优化未来决策
3. **知识图谱更新滞后** - 新的经验和教训无法及时沉淀

### 当前架构缺口

根据 ADR-050 的分析：

| OADP 阶段 | 当前状态 | 缺口 |
|-----------|----------|------|
| 感知 Observe | ⚠️ 部分 | 缺乏统一抽象层 |
| 理解 Analyze | ✅ 良好 | 细节可优化 |
| 决策 Decide | ⚠️ 部分 | Decision Recommendation 未实现（已补充） |
| 执行 Perform | ⚠️ 部分 | **缺少闭环反馈** |

## 决策

### 反馈类型

| 反馈类型 | 来源 | 内容 | 用途 |
|----------|------|------|------|
| `action_result` | 执行层 | 动作执行结果 | 评估决策有效性 |
| `decision_feedback` | 用户/系统 | 决策采纳情况 | 优化推荐算法 |
| `outcome_deviation` | 分析器 | 预期vs实际偏差 | 调整模型参数 |
| `lesson_learned` | 用户 | 经验教训 | 知识沉淀 |

from typing import Dict, Any, Optional
from datetime import datetime
from enum import Enum

class FeedbackType(str, Enum):
    ACTION_RESULT = "action_result"
    DECISION_FEEDBACK = "decision_feedback"
    OUTCOME_DEVIATION = "outcome_deviation"
    LESSON_LEARNED = "lesson_learned"


class ActionFeedback(BaseModel):
    """动作执行反馈"""
    action_id: str
    decision_id: Optional[str]
    executed_at: datetime
    duration_ms: float
    outcome: str  # success, failure, partial
    result_data: Dict[str, Any]
    error_message: Optional[str]


class FeedbackCollector:

    反馈收集器

    收集执行层产出的各类反馈

        """收集反馈，返回反馈ID"""
        pass

    async def query_feedback(
        self,
        decision_id: str,
        limit: int = 10
    ) -> List[ActionFeedback]:

        pass

class FeedbackAnalyzer:
    """
    反馈分析器

    分析反馈数据，识别模式和偏差
    """

    async def analyze_deviation(
        self,
        feedback: ActionFeedback,
        expected_outcome: Dict[str, Any]
    ) -> Dict[str, Any]:
        """
        分析预期与实际的偏差

        Returns:
            {
                "deviation_score": 0.3,  # 偏差程度
                "deviation_factors": ["time_delay", "quality_drop"],
                "root_causes": ["resource_constraint", "external_factor"]
            }
        """
        pass

    async def identify_patterns(
        self,
        feedback_history: List[ActionFeedback]
    ) -> Dict[str, Any]:
        """识别反馈模式"""
        pass


# odap/biz/feedback/aggregator.py
class FeedbackAggregator:
    """
    反馈聚合器

    将分析结果聚合并更新知识图谱
    """

    async def aggregate_and_update(
        self,
        decision_id: str,
        analysis_result: Dict[str, Any]
    ) -> bool:
        """
        聚合反馈并更新知识图谱

        1. 创建反馈事件节点
        2. 关联到原始决策
        3. 更新相关实体属性
        """
        pass


# odap/biz/feedback/loop.py
class FeedbackLoop:
    """
    反馈闭环管理器

    协调反馈收集、分析、聚合的完整流程
    """

    def __init__(
        self,
        collector: FeedbackCollector,
        analyzer: FeedbackAnalyzer,
        aggregator: FeedbackAggregator,
        graphiti_client: GraphitiClient,
    ):
        self.collector = collector
        self.analyzer = analyzer
        self.aggregator = aggregator
        self.graphiti = graphiti_client

    async def close_loop(
        self,
        action_feedback: ActionFeedback,
        expected_outcome: Optional[Dict[str, Any]] = None
    ) -> Dict[str, Any]:
        """
        执行完整的反馈闭环

        流程：
        1. 收集反馈
        2. 分析偏差（如有预期结果）
        3. 聚合更新知识图谱
        4. 返回分析摘要
        """
        # 1. 收集
        feedback_id = await self.collector.collect(action_feedback)

        # 2. 分析
        analysis = {}
        if expected_outcome:
            analysis = await self.analyzer.analyze_deviation(
                action_feedback,
                expected_outcome
            )

        # 3. 聚合更新
        await self.aggregator.aggregate_and_update(
            decision_id=action_feedback.decision_id,
            analysis_result={
                "feedback_id": feedback_id,
                "feedback": action_feedback.model_dump(),
                "analysis": analysis,
            }
        )

        return {
            "feedback_id": feedback_id,
            "analysis": analysis,
            "graph_updated": True,
        }
```

### 知识图谱更新策略

反馈更新遵循以下策略：

| 反馈类型 | 图谱操作 | 关系 |
|----------|----------|------|
| action_result | 创建 Event 节点 | `:CAUSED -> Decision` |
| outcome_deviation | 更新 Decision 属性 | `:HAS_DEVIATION` |
| lesson_learned | 创建 Fact 节点 | `:INFORMS -> Decision` |

    action_id: $action_id,
    outcome: $outcome,
    timestamp: datetime()
})
CREATE (f)-[:CAUSED {by: 'action'}]->(d:Decision {id: $decision_id})
CREATE (f)-[:RELATED_TO]->(e:Entity {id: $entity_id})
RETURN f
```

## 后果

### 正面

1. **决策质量可量化** - 通过反馈追踪，评估决策推荐的有效性
2. **持续学习能力** - 历史反馈用于优化未来决策
3. **知识沉淀自动化** - 经验教训自动写入知识图谱
4. **问题根因追溯** - 偏差分析帮助定位问题根源

### 负面/权衡

1. **引入新模块** - 增加系统复杂度（反馈收集、分析、聚合）
2. **延迟感知更新** - 反馈处理需要时间，感知更新非实时
3. **反馈质量依赖** - 反馈数据质量直接影响学习效果

### 依赖关系

- 依赖 `M-01 Graphiti` - 知识图谱写入
- 依赖 `M-13 Decision Recommendation` - 决策反馈关联
- 依赖 `M-07 Audit Log` - 审计追踪
