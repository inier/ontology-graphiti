# ODAP 可扩展架构设计 — Overview（2026-07-08）

## 交付物
- **主设计文档**：`docs/02-architecture/SCALABLE_ARCHITECTURE_2026.md`
- **5 个新 ADR**（均 Proposed）：
  - ADR-061 领域 Skill 插件化打包与契约测试
  - ADR-062 知识图谱读写分离与冷热分层
  - ADR-063 租户感知隔离与部署蓝图
  - ADR-064 可观测性基线（OpenTelemetry 统一追踪）
  - ADR-065 微服务拆分演进预案与触发条件

## 核心结论
在**模块化单体（ADR-046）**底座上，针对三大扩展驱动用四根支柱撑起近一年（6–12 月）的扩展需求，所有决策保持**可逆**，微服务拆分仅作为触发条件满足后的预案。

| 扩展驱动 | 策略 | 关键决策 |
|----------|------|----------|
| 领域 Skill / 团队规模 | 插件化打包 + 契约测试 | ADR-061（保持单进程，独立版本/灰度） |
| 知识图谱数据规模 | 读写分离 + 向量 offload（近）+ 冷热分层（中），分片推迟 | ADR-062 |
| 多租户 / 交付部署 | 租户感知隔离 + 部署蓝图（每租户独立部署） | ADR-063 |
| 横切前提 | 统一追踪/指标/日志 | ADR-064（Q1 最先做） |
| 演进护栏 | 拆分触发条件 + 抽取 playbook | ADR-065（补 ADR-046） |

## 季度路线图
- **Q1**：可观测性基线 + `ISkill` 契约 + `TenantIsolator` 原型 + 图谱读副本/向量 offload
- **Q2**：冷热分层 PoC + 部署蓝图/租户开通自动化 + 内部 Skill 市场 + 压测
- **Q3**：模块级熔断/舱壁 + 读副本自动扩缩 + 多租户管理台
- **Q4**：微服务拆分预案定稿 + 容量规划 + 演练

## 设计哲学
延迟复杂度（delay complexity）、可逆优先、YAGNI——与 ADR-046 / ADR-030 一脉相承。图谱分片、多区域、Service Mesh 明确推迟到 Phase 5+。
