### Why It Matters

The same SQL injection class fixed in `audit_sqlite_channel.py` (R-P0-004) exists in the
Cypher path. User-controlled fields (`filter.workspace_id`, `filter.trace_id`, `filter.actor_ids`,
`filter.limit`) are directly interpolated into Cypher. An attacker who can submit audit filter
parameters can:

1. **String-escape**: `"...workspace\" OR MATCH (admin) DETACH DELETE admin //"` to break out of the quoted value
2. **Inject arbitrary Cypher**: e.g., add `MATCH (u:User {role:'admin'}) SET u.deleted = true` to the query
3. **Bypass authorization**: read audit logs from workspaces the attacker doesn't own

The sibling `audit_sqlite_channel.py` was already fixed in R-P0-004 — this finding closes
the remaining gap in the audit subsystem.

### Fix

Use Neo4j parameterized queries throughout:

```python
def _query_with_neo4j(self, filter: AuditFilter) -> List[AuditEvent]:
    from neo4j import AsyncSession

    # Validate limit (defense in depth)
    bounded_limit = max(1, min(int(filter.limit), 1000))

    with self._graph_manager.neo4j_driver.session() as session:
        # Build Cypher with $param placeholders
        cypher = """
            MATCH (n:AuditLog)
            WHERE ($ws IS NULL OR n.workspace_id = $ws)
              AND ($trace IS NULL OR n.trace_id = $trace)
              AND ($uids IS NULL OR n.user IN $uids)
            RETURN n
            ORDER BY n.timestamp DESC
            LIMIT $limit
        """
        result = session.run(
            cypher,
            ws=filter.workspace_id or None,
            trace=filter.trace_id or None,
            uids=list(filter.actor_ids) if filter.actor_ids else None,
            limit=bounded_limit,
        )
        return [self._convert_to_audit_event(dict(record["n"])) for record in result]
```

### Why It Matters

Long functions are hard to:
1. **Test in isolation** — single test exercises many branches
2. **Reuse** — entire function is the unit of reuse
3. **Review** — reviewer cannot hold whole function in working memory
4. **Modify safely** — high risk of unintended side effects

### Fix Strategy (Incremental)

Don't refactor all 213 at once. Instead:

1. **Tag functions** exceeding 40 lines with `# TODO(refactor:R-P3-001)` — easy grep-based tracking
2. **Split during routine maintenance** — when touching a function for any other reason, split it as part of that PR
3. **Prioritize** functions with:
   - High call frequency (`graph_service.py`, `qa_engine.py`)
   - High complexity (cyclomatic > 10)
   - Public API exposure

```python
# tests/unit/test_function_length.py
import ast
from pathlib import Path

MAX_FUNCTION_LINES = 40

def test_no_function_exceeds_40_lines():
    violations = []
    for f in Path("odap").rglob("*.py"):
        if "tests" in str(f) or "migration" in str(f):
            continue
        try:
            src = f.read_text(encoding="utf-8")
        except (UnicodeDecodeError, OSError):
            continue
        try:
            tree = ast.parse(src)
        except SyntaxError:
            continue
        for node in ast.walk(tree):
            if isinstance(node, (ast.FunctionDef, ast.AsyncFunctionDef)):
                n = (node.end_lineno or node.lineno) - node.lineno + 1
                if n > MAX_FUNCTION_LINES:
                    violations.append(f"{f}:{node.lineno} {n}L {node.name}")
    assert not violations, f"Found {len(violations)} functions > 40 lines"
```
