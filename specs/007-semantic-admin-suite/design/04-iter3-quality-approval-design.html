② Gate 1 · 句法/结构闸（7 项子检查，权重 35%）

目标：纯 Pydantic/正则/字符串检查，无外部依赖，不做推理
权重：w₁ = 0.35（3 关中最高——基础格式错直接否决 35% 分）
子指标算法阈值失败动作
G1.1 名称合规正则 /^[\u4e00-\u9fa5A-Za-z][\u4e00-\u9fa5A-Za-z0-9_·-]{0,39}$/（中文+英文+数字+下划线+中划线+点，长度 1~40）布尔FAIL 得分 -0.35
G1.2 en_mapping 可用字段 en 非空且符合 PascalCase /^[A-Z][a-zA-Z0-9]*$/布尔WARN 得分 -0.08，候选自动查 USL 域 en_mapping 尝试回退补全
G1.3 semantic_type ∈ 合法枚举{对象类型, 关系类型, 属性, 动作类型, 过程类型, 规则类型}31}布尔FAIL 得分 -0.15，改回默认 "对象类型"
G1.4 同义词集大小在 [0, 30] 内0 ≤ len(synonyms) ≤ 30布尔WARN 截断到前 30 个
G1.5 同义词去重率len(set(synonyms)) / max(1,len(synonyms))≥ 0.98WARN 自动去重
G1.6 canonical 与同义词无互相包含环canonical 不在 synonyms 中；同义词不包含 canonical布尔WARN 自动剔除
G1.7 与 USL 同名冲突检查（去重）对同一 domain_id，canonical 已存在于 usl_terms → 标 origin=usl 并去重合并布尔INFO 合并为 origin=usl，不失败

③ Gate 2 · 语义一致性闸（4 项子检查，权重 40%）

目标：避免"刘备既是势力又是人物"这种明显自相矛盾
权重：w₂ = 0.40（最高）  失败成本：高（语义错 = Schema 错）
子指标算法阈值失败动作
G2.1 USL Disjointness 不相交检查查 usl_disjoint_pairs：若 C₁=人物 与 C₂=势力 ∈ disjoint → 候选不能同时 is_a(C₁) 且 is_a(C₂)布尔FAIL 得分 -0.40，写回候选 warning_message
G2.2 基数约束检查关系类型候选查 usl_cardinality：min ≤ 实际出现 ≤ maxmin=0 max=NULLWARN 得分 -0.06 每超 10%
G2.3 is_a 无环检查（L3 草稿层级）对 USL__IS_A_DRAFT 关系做拓扑排序：若 DAG 有环 → 失败布尔FAIL 得分 -0.20，列出环边
G2.4 LLM 语义一致性 Judge（可选，可关闭）10 tokens 以内的 LLM prompt："候选 {c} 与 USL 中 {x1,x2,...} 是否矛盾？只输出 yes/no + 1 行理由"yes/noWARN 得分 -0.05 每一次 no（关闭时跳过）
💡 G2.4 可选开关：全局配置项 global_config.quality_gate.enable_llm_judge = True/False（默认 False，避免 LLM 超时）

④ Gate 3 · 领域质量闸（5 项子指标，权重 25%）

目标：衡量"这个候选是否有价值"，不是对错而是密度
权重：w₃ = 0.25
子指标公式（连续分 0~1）权重子比低分动作
G3.1 属性密度s = min(1, 关系类型出现次数 / 5)  （属性越多越有价值，≥ 5 满分）0.30综合分 < 0.3 → LOW_QUALITY
不阻断审批，但审核台打灰色高亮
G3.2 词频覆盖率s = min(1, doc_hits / 10)  （在 10 个以上文档片段出现=满分）0.20
G3.3 同义词丰富度s = min(1, (同义词数+近义词数+别名数)/5)0.15
G3.4 USL 对齐率（反向：新颖度）s = 1 − usl_align_confidence（和 USL 越不像，价值越大=补空白）0.15
G3.5 层级贡献度s = min(1, number_of_L3_children_estimation / 3)  （作为父节点能挂多少子节点估计）0.20

总得分公式

total_score = 0.35 × gate1 + 0.40 × gate2 + 0.25 × gate3

阈值分层：
  total_score ≥ 0.85 → HIGH        审核台绿色（直接 AUTO_APPROVE? 默认关闭）
  0.70 ≤ total < 0.85 → MEDIUM     审核台白色（正常审核）
  0.50 ≤ total < 0.70 → LOW        审核台黄色（需 auditor 格外注意）
  total_score < 0.50 → VERY_LOW    审核台灰色（建议拒绝）

⑥ OPA 策略 & Depends 权限钩子（2 级审批权限模型）

6a. Rego 新策略文件：policies/semantic_admin.rego

# schema_auditor = 工作空间级的"本体审核员"
# admin           = 全局级的"平台管理员"
package semantic_admin

default allow = false

# --- 规则 1: schema_auditor 对本工作空间内候选有"初审权限"（PENDING_REVIEW → AUDITOR_*） ---
allow {
    input.action == "audit_candidate"
    input.ws_role == "schema_auditor"        # JWT ws_role 字段
    input.candidate.workspace_id == input.ws_id
    input.candidate.status == "PENDING_REVIEW"
}

# --- 规则 2: admin 有"终局审批权限"（ADMIN_PENDING → APPROVED / REJECTED） ---
allow {
    input.action == "final_approve"
    input.role == "admin"                    # JWT 全局 role
    input.candidate.status == "ADMIN_PENDING"
}

# --- 规则 3: auto-skip（总得分 ≥ 0.7）只允许由系统 service_account 触发 ---
allow {
    input.action == "auto_approve_skip_admin"
    input.subject == "service:semantic-admin-workflow"
    input.quality_report.total_score >= 0.7
}

# --- 规则 4: 任何人都可以读质量报告 ---
allow {
    input.action == "read_quality_report"
}

# --- 规则 5: 修改/拒绝时必填 comment ---
deny[message] {
    input.action == "audit_candidate"
    input.audit_action == "MODIFY"
    not input.comment
    message := "MODIFY 必须填写 comment"
}
deny[message] {
    input.action == "audit_candidate"
    input.audit_action == "REJECT"
    not input.comment
    message := "REJECT 必须填写拒绝理由"
}
