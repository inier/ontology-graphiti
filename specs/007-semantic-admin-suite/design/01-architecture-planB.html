② 4 个迭代拆解（Scope 边界 × 交付物 × 验收）

Iteration 1 · USL 服务化深度清理 — Week 1

🟢 基线

核心目标：消灭 semantic_config.py 静态硬编码；把 QA 问答逻辑迁到正确域；为后续 3 个迭代打地基

类型交付物
迁移intent_parser / query_planner / disambiguator 三个文件 + 单测 → biz/data/qa/nl_pipeline/
删除/api/semantic 中 parse_intent / plan_tasks / disambiguate 三个路由（更新 router_registry）
新建biz/semantic_admin/usl_manager + SQLite 存储 + 完整 CRUD API
新建前端 /semantic-admin/usl 配置页（语义规范术语表格、同义词簇编辑、en_mapping 编辑）
🔁 数据三国/西游现有 SANGUO_SEMANTIC / XYOU_SEMANTIC dict 数据 → USL DB 初始化 migration 脚本

Iteration 2 · L1-L2 概念抽取 + Candidate 存储 — Week 2-3

🟡 核心

核心目标：Hyper-Extract concept_graph 正式接入 OL，产生真 Schema Candidate，不再人工写 scripts/build_*_ontology.py OBJECT_TYPES

类型交付物
新建biz/semantic_admin/ol_pipeline/ 编排框架 + L1 术语 + L2 概念聚合计（BGE 余弦 + USL 对齐）
新建biz/semantic_admin/candidate_store/ + SQLite(元数据)·Neo4j(_schema_graph) 双写 DDL
新建前端 /semantic-admin/pipeline：文档上传 → 触发 OL → 6 层进度条 → 每一层候选数统计
🔁 APIExtractService 新增 mode="schema_learning"（默认 concept_graph，返回带置信度连续分）

Iteration 3 · 质量闸 + 2 级审批 + 细粒度角色 — Week 4-5

⭐ 价值交付

核心目标：候选不能直接进 Ontology，必须 3 关 + 2 审，质量保证的核心闸

类型交付物
新建biz/semantic_admin/quality_gate/ 3 关：句法(Pydantic)·语义(DL 可满足性)·领域密度(5 指标)
新建biz/semantic_admin/approval_workflow/ schema_auditor + admin 2 级 Depends；OPA Rego 策略
新建前端 /semantic-admin/candidates 审核台：提案卡模式·置信度分层·通过/修改/拒绝三按钮·审批流记录
🔁 权限roles 模块新增 schema_auditor 细粒度角色 + RoleManager 页 + JWT ws_role 校验

Iteration 4 · HITL 飞轮 + L3-L6 全量 + 清理 — Week 6

🔷 闭环

核心目标：自动闭环 + 覆盖 6 层全量 + 清理 old semantic_layer 目录，标志 Feature 闭环

类型交付物
新建usl_writeback/ 已批准 Candidate → USL canonical_terms/stoplist 自动写入 Hook
新建ol_pipeline 中 L3(FCA 分类)·L4(关系扩展)·L5(SchemaFusion)·L6(AxiomInductor)
新建前端 /semantic-admin/quality 指标面板：USL 对齐率·属性密度·审核积压·通过率趋势
清理删除 design/schema/semantic_layer 老目录 + 死代码 + 老单测用例更新路径
🔁 集成scripts/build_ecommerce_ontology.py 改造：可选 --from-doc 参数走 OL 自动生成 + 人工对比 OBJECT_TYPES 差异率
