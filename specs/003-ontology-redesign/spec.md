# Feature Specification: 本体设计器彻底重构

**Feature Branch**: `003-ontology-redesign`

**Created**: 2026-06-09

**Status**: Draft

**Input**: User description: "彻底重构本体设计能力，支持以下几种方式：1. 手工定义本体结构，结构要包括业务过程、逻辑（本体论的function和function type）、规则和指标等，与子菜单的业务过程、逻辑、规则和指标是同一份定义，只是后者可独立版块单独维护实例数据；2. 通过接入外部数据库直接大模型抽取；3. 支持自然语言输入需求，从返回的非结构化数据（没有数据时，发起联网检索获取数据）中提取对象（object type）、关系（link type）、规则（rules）和动作（action type）等。如果之前已经存在了本体，需要先选择一个本体或新建本体（本体版本管理），再进行选择设计方式。提供其他一些本体管理的功能，如本体图谱展示（缩放、平移等，之前的语义图谱已经实现了部分，菜单被隐藏了），边、节点编辑和查看等功能。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 手工定义本体结构 (Priority: P1)

用户在进入本体设计器后，选择一个已有本体或新建本体（含版本管理），然后通过手工方式定义本体结构。手工定义的内容包括：对象类型（Object Type）、关系类型（Link Type）、动作类型（Action Type）、业务过程（Business Process）、逻辑函数（Function / Function Type）、规则（Rule）和指标（Indicator）。这些定义与"业务"子菜单下的业务过程、逻辑、规则、指标页面共享同一份数据定义——本体设计器中定义的是结构（Schema），子菜单页面维护的是该结构下的实例数据。

**Why this priority**: 手工定义是本体设计最基础、最核心的能力，是其他两种设计方式（数据库抽取、自然语言提取）的产出物归宿。没有统一的手工定义能力，其他方式的产出无法被有效管理和复用。

**Independent Test**: 可通过在本体设计器中创建一个新本体，手工添加对象类型、关系类型、动作类型、业务过程、逻辑函数、规则和指标，然后在"业务"子菜单下验证这些结构定义已同步可见，且能在子菜单中创建对应的实例数据。

**Acceptance Scenarios**:

1. **Given** 用户已进入本体设计器，**When** 用户选择"新建本体"并填写名称和描述，**Then** 系统创建一个新本体（含初始版本 v0.1.0），并进入设计界面
2. **Given** 用户已选择一个本体，**When** 用户在"对象类型"区域点击"新增"，填写名称、属性、分类级别，**Then** 系统保存该对象类型定义，并同步到对象管理页面的类型列表
3. **Given** 用户已定义了对象类型 A 和 B，**When** 用户添加关系类型（源=A，目标=B，关系名=包含，基数=1:N），**Then** 系统保存该关系类型定义，并在图谱中显示 A→B 的连线
4. **Given** 用户已定义了对象类型 A，**When** 用户添加动作类型（名称=启动，目标类型=A，参数列表），**Then** 系统保存该动作类型定义
5. **Given** 用户已在本体设计器中定义了业务过程"订单处理"，**When** 用户切换到"业务 > 业务过程"子菜单，**Then** 该业务过程的结构定义可见，且用户可创建"订单处理"的实例数据
6. **Given** 用户已在本体设计器中定义了逻辑函数"计算折扣"，**When** 用户切换到"业务 > 逻辑"子菜单，**Then** 该逻辑函数的结构定义可见，且用户可创建"计算折扣"的实例数据
7. **Given** 用户已在本体设计器中定义了规则"库存预警"，**When** 用户切换到"业务 > 规则"子菜单，**Then** 该规则的结构定义可见，且用户可创建"库存预警"的实例数据
8. **Given** 用户已在本体设计器中定义了指标"月销售额"，**When** 用户切换到"业务 > 指标"子菜单，**Then** 该指标的结构定义可见，且用户可创建"月销售额"的实例数据

---

### User Story 2 - 通过外部数据库抽取本体 (Priority: P2)

用户在本体设计器中选择"从数据库抽取"方式，配置外部数据库连接（支持 MySQL、PostgreSQL、SQLite 等），系统读取数据库的 Schema 信息（表、列、外键、索引），通过大模型将数据库 Schema 自动映射为本体定义——表映射为对象类型、外键映射为关系类型、存储过程/触发器映射为动作类型、CHECK 约束映射为规则。用户可预览和编辑抽取结果，确认后写入本体。

**Why this priority**: 数据库抽取是快速构建本体的高效方式，特别适合已有数据库的存量系统。但依赖手工定义能力作为基础，因此优先级次之。

**Independent Test**: 可通过连接一个示例数据库（如 SQLite 示例文件），执行抽取流程，验证生成的对象类型、关系类型、动作类型和规则是否正确映射。

**Acceptance Scenarios**:

1. **Given** 用户已选择一个本体，**When** 用户选择"从数据库抽取"并填写数据库连接信息（类型、主机、端口、数据库名、用户名、密码），**Then** 系统测试连接并显示连接状态
2. **Given** 数据库连接成功，**When** 用户点击"开始抽取"，**Then** 系统读取数据库 Schema 并通过大模型生成本体定义预览
3. **Given** 抽取结果预览已展示，**When** 用户编辑某个对象类型的属性（如修改名称、添加分类级别），**Then** 编辑结果实时反映在预览中
4. **Given** 用户确认抽取结果，**When** 用户点击"确认导入"，**Then** 系统将抽取的本体定义写入当前本体版本，并在设计器中可见
5. **Given** 数据库连接失败，**When** 用户尝试抽取，**Then** 系统显示明确的错误信息（如连接超时、认证失败、网络不通）

---

### User Story 3 - 自然语言输入提取本体 (Priority: P2)

用户在本体设计器中选择"自然语言提取"方式，输入一段自然语言描述的需求文本。系统将文本发送给大模型，从中提取对象类型（Object Type）、关系类型（Link Type）、规则（Rules）和动作类型（Action Type）。如果用户没有提供足够的数据，系统可自动发起联网检索获取相关领域知识，再从检索结果中提取本体元素。用户可预览和编辑提取结果，确认后写入本体。

**Why this priority**: 自然语言提取降低了本体构建的门槛，让非技术用户也能参与本体设计。与数据库抽取同为 P2，两者是互补的自动化构建方式。

**Independent Test**: 可通过输入一段业务描述（如"电商系统需要管理用户、商品和订单，用户可以下单购买商品，订单包含多个商品项，库存不足时触发补货规则"），验证系统提取的对象类型、关系类型、规则和动作类型是否合理。

**Acceptance Scenarios**:

1. **Given** 用户已选择一个本体，**When** 用户选择"自然语言提取"并输入需求描述，**Then** 系统将文本发送给大模型进行提取
2. **Given** 大模型返回提取结果，**When** 结果展示在预览区，**Then** 用户可查看提取的对象类型、关系类型、规则和动作类型列表
3. **Given** 用户输入的需求描述信息不足，**When** 系统判断需要补充领域知识，**Then** 系统自动发起联网检索获取相关数据，并基于检索结果继续提取
4. **Given** 提取结果预览已展示，**When** 用户编辑某个提取结果（如修改对象类型名称、删除不合理的规则），**Then** 编辑结果实时反映在预览中
5. **Given** 用户确认提取结果，**When** 用户点击"确认导入"，**Then** 系统将提取的本体定义写入当前本体版本

---

### User Story 4 - 本体版本管理 (Priority: P1)

用户在进入本体设计器时，如果已存在本体，需要先选择一个本体或新建本体。选择已有本体后，用户可查看该本体的版本历史，在不同版本间切换、对比差异、回滚到历史版本。每次通过手工定义、数据库抽取或自然语言提取修改本体结构后，系统自动创建一个新版本（或追加到当前版本），用户也可手动提交版本快照。

**Why this priority**: 版本管理是本体设计的基础保障，确保设计过程的可追溯性和可回滚性。与手工定义同为 P1，因为版本管理是所有设计方式的前置条件。

**Independent Test**: 可通过创建一个本体，进行多次修改，验证版本历史记录是否完整，版本对比是否准确，回滚是否生效。

**Acceptance Scenarios**:

1. **Given** 用户进入本体设计器，**When** 已存在至少一个本体，**Then** 系统显示本体选择列表，用户可选择一个本体进入设计
2. **Given** 用户进入本体设计器，**When** 用户选择"新建本体"，**Then** 系统创建新本体并生成初始版本
3. **Given** 用户正在编辑一个本体，**When** 用户修改了对象类型定义并保存，**Then** 系统自动追加到当前版本（版本号不变，内容更新）
4. **Given** 用户正在编辑一个本体，**When** 用户点击"提交版本"，**Then** 系统锁定当前版本为稳定版本，并创建新的工作版本
5. **Given** 用户查看版本历史，**When** 用户选择两个版本进行对比，**Then** 系统显示两个版本之间的差异（新增/修改/删除的对象类型、关系类型等）
6. **Given** 用户查看版本历史，**When** 用户选择一个历史版本并点击"回滚"，**Then** 系统将本体恢复到该版本的状态

---

### User Story 5 - 本体图谱展示与交互 (Priority: P1)

用户在本体设计器中可以查看本体的图谱可视化展示。图谱以节点表示对象类型，以边表示关系类型。用户可以缩放、平移图谱，点击节点查看对象类型详情，点击边查看关系类型详情，编辑节点和边的属性。之前被隐藏的语义图谱菜单应恢复可见。

**Why this priority**: 图谱展示是本体设计器最直观的交互方式，是用户理解和验证本体结构的核心手段。与手工定义、版本管理同为 P1，构成本体设计器的三大核心能力。

**Independent Test**: 可通过创建包含多个对象类型和关系类型的本体，验证图谱是否正确渲染，缩放/平移是否流畅，节点/边点击是否显示详情，编辑是否生效。

**Acceptance Scenarios**:

1. **Given** 用户已选择一个包含对象类型和关系类型的本体，**When** 用户切换到"图谱"视图，**Then** 系统以节点（对象类型）和边（关系类型）渲染图谱
2. **Given** 图谱已渲染，**When** 用户使用鼠标滚轮缩放，**Then** 图谱平滑缩放，缩放级别实时显示
3. **Given** 图谱已渲染，**When** 用户拖拽画布，**Then** 图谱平移，不出现卡顿
4. **Given** 图谱已渲染，**When** 用户点击一个节点，**Then** 系统高亮该节点及其关联的边和节点，并弹出详情面板显示对象类型属性
5. **Given** 图谱已渲染，**When** 用户点击一条边，**Then** 系统高亮该边，并弹出详情面板显示关系类型属性
6. **Given** 用户在节点详情面板中，**When** 用户编辑对象类型的属性（如添加新属性、修改名称），**Then** 修改即时保存并反映在图谱中
7. **Given** 用户在边详情面板中，**When** 用户编辑关系类型的属性（如修改基数、关系名），**Then** 修改即时保存并反映在图谱中
8. **Given** 语义图谱菜单当前被隐藏，**When** 系统部署完成后，**Then** 语义图谱菜单恢复可见

---

### Edge Cases

- 当用户在数据库抽取过程中连接中断时，系统应保留已抽取的部分结果，允许用户重新连接后继续
- 当自然语言提取的结果与已有本体定义冲突（如同名对象类型但属性不同）时，系统应提示冲突并让用户选择合并或覆盖策略
- 当用户回滚到历史版本时，当前未提交的修改应提示用户保存或丢弃
- 当本体中没有任何对象类型时，图谱视图应显示空状态提示，引导用户添加第一个对象类型
- 当数据库 Schema 非常大（数百张表）时，抽取过程应支持分批抽取和进度显示
- 当联网检索无法获取数据时（网络不通或无相关结果），系统应提示用户手动补充信息
- 当用户在子菜单页面修改了实例数据后，本体设计器中的结构定义不应受影响（结构与实例分离）

## Requirements *(mandatory)*

### Functional Requirements

**本体入口与版本管理**

- **FR-001**: 系统必须在本体设计器入口提供本体选择器，允许用户从已有本体列表中选择一个本体进入设计
- **FR-002**: 系统必须允许用户在入口处新建本体（填写名称、描述），自动创建初始版本
- **FR-003**: 系统必须支持本体版本管理，包括：自动追加修改到当前版本、手动提交版本快照、版本历史查看、版本差异对比、版本回滚
- **FR-004**: 系统必须在用户进入设计器时，如果未选择本体，引导用户先选择或新建本体

**手工定义本体结构**

- **FR-005**: 系统必须支持手工定义对象类型（Object Type），包括：名称、显示名称、属性列表（名称、数据类型、是否必填、默认值、分类级别）、分类级别
- **FR-006**: 系统必须支持手工定义关系类型（Link Type），包括：名称、源对象类型、目标对象类型、基数（1:1/1:N/N:1/N:N）、关系类型（关联/组合/依赖/继承）
- **FR-007**: 系统必须支持手工定义动作类型（Action Type），包括：名称、目标对象类型、参数列表、描述
- **FR-008**: 系统必须支持手工定义业务过程（Business Process），包括：名称、流程节点列表、关联对象、YAML 定义
- **FR-009**: 系统必须支持手工定义逻辑函数（Function / Function Type），包括：名称、逻辑类型（过滤/转换/验证/计算）、逻辑表达式、关联对象
- **FR-010**: 系统必须支持手工定义规则（Rule），包括：名称、触发条件、约束要求、优先级、关联对象
- **FR-011**: 系统必须支持手工定义指标（Indicator），包括：名称、指标类型（KPI/度量/维度）、计算公式、单位、关联对象

**结构与实例统一**

- **FR-012**: 本体设计器中定义的业务过程、逻辑函数、规则、指标的结构定义，必须与"业务"子菜单下的业务过程、逻辑、规则、指标页面共享同一份数据源
- **FR-013**: 本体设计器中只能编辑结构定义（Schema），子菜单页面维护该结构下的实例数据
- **FR-014**: 在子菜单页面创建实例数据时，必须从本体设计器定义的结构中选择（如下拉选择业务过程名称）
- **FR-015**: 对象类型定义必须与对象管理页面的类型管理共享同一份数据源

**数据库抽取**

- **FR-016**: 系统必须支持配置外部数据库连接，支持 MySQL、PostgreSQL、SQLite 三种数据库类型
- **FR-017**: 系统必须读取数据库 Schema（表、列、外键、索引、CHECK 约束、存储过程/触发器），通过大模型自动映射为本体定义
- **FR-018**: 映射规则：表→对象类型、外键→关系类型、存储过程/触发器→动作类型、CHECK 约束→规则
- **FR-019**: 系统必须在抽取完成后提供预览界面，允许用户编辑和确认抽取结果
- **FR-020**: 系统必须在数据库连接失败时提供明确的错误信息

**自然语言提取**

- **FR-021**: 系统必须支持用户输入自然语言需求描述，通过大模型提取对象类型、关系类型、规则和动作类型
- **FR-022**: 当用户输入的信息不足时，系统必须自动发起联网检索获取补充数据，再从检索结果中继续提取
- **FR-023**: 系统必须在提取完成后提供预览界面，允许用户编辑和确认提取结果
- **FR-024**: 当提取结果与已有本体定义冲突时，系统必须提示冲突并提供合并或覆盖选项

**图谱展示与交互**

- **FR-025**: 系统必须提供本体图谱可视化视图，以节点表示对象类型、以边表示关系类型
- **FR-026**: 系统必须支持图谱的缩放（鼠标滚轮/按钮）和平移（拖拽画布）
- **FR-027**: 系统必须支持点击节点查看对象类型详情，点击边查看关系类型详情
- **FR-028**: 系统必须支持在详情面板中编辑节点（对象类型属性）和边（关系类型属性），修改即时保存
- **FR-029**: 系统必须恢复被隐藏的语义图谱菜单入口
- **FR-030**: 系统必须支持图谱的多布局切换（力导向、环形、层次、辐射）
- **FR-031**: 系统必须支持图谱的搜索定位（按名称搜索节点并高亮居中）

### Key Entities

- **Ontology**: 本体，顶级容器，包含名称、描述、创建时间、当前版本号。一个本体属于一个工作空间下的一个场景
- **OntologyVersion**: 本体版本，包含版本号、变更日志、状态（工作版本/稳定版本）、父版本指针、快照数据
- **ObjectType**: 对象类型（Schema 层），定义一类实体的属性结构，属于某个本体版本
- **LinkType**: 关系类型（Schema 层），定义两个对象类型之间的关系，属于某个本体版本
- **ActionType**: 动作类型，定义可对对象类型执行的操作，属于某个本体版本
- **BusinessProcess**: 业务过程（Schema 层），定义业务流程的结构，属于某个本体版本
- **FunctionDefinition**: 逻辑函数定义（Schema 层），定义逻辑函数的结构，属于某个本体版本
- **RuleDefinition**: 规则定义（Schema 层），定义业务规则的结构，属于某个本体版本
- **IndicatorDefinition**: 指标定义（Schema 层），定义业务指标的结构，属于某个本体版本
- **DatabaseConnection**: 数据库连接配置，包含数据库类型、连接参数、认证信息
- **ExtractionResult**: 抽取/提取结果，包含从数据库或自然语言中提取的本体元素列表及冲突标记

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户可在 5 分钟内完成一个包含 5 个对象类型、3 个关系类型、2 个动作类型的本体手工定义
- **SC-002**: 本体设计器中定义的结构与子菜单页面可见的结构 100% 一致，无数据不同步情况
- **SC-003**: 数据库抽取功能可在 2 分钟内完成一个 20 表数据库的 Schema 读取和本体映射
- **SC-004**: 自然语言提取功能可在 30 秒内返回提取结果（不含联网检索时间）
- **SC-005**: 图谱视图支持至少 100 个节点和 200 条边的流畅渲染（缩放/平移无卡顿）
- **SC-006**: 版本回滚操作在 3 秒内完成，数据状态与目标版本完全一致
- **SC-007**: 90% 的用户可在首次使用时无需培训即可完成本体创建和基本定义操作
- **SC-008**: 子菜单页面创建实例数据时，结构选择下拉列表加载时间不超过 1 秒

## Assumptions

- 用户已具备基本的知识图谱或本体概念理解，知道什么是对象类型、关系类型等
- 数据库抽取功能需要用户具备数据库连接信息（主机、端口、用户名、密码），且数据库可从 ODAP 服务端网络可达
- 自然语言提取依赖大模型服务可用，联网检索依赖 Tavily 或 DuckDuckGo 等搜索服务可用
- 本体设计器是单用户操作场景，暂不考虑多人同时编辑同一本体的并发冲突（已有分支/合并机制可后续启用）
- 对象类型定义与对象管理页面的类型管理合并后，原有的 OMS 独立类型定义将迁移到统一模型
- 业务过程、逻辑、规则、指标的"结构定义"与"实例数据"采用同一存储但不同 API 端点区分
- 图谱可视化复用现有的 GraphCanvas 组件（AntV G6 5.x），不重新开发
- 语义图谱菜单恢复可见仅需修改前端路由配置，无需后端改动
