## 一、项目概述

### 1.1 项目背景

Graphiti 是一个通用的本体驱动分析决策平台（Ontology-Driven Analysis & Decision Platform, ODAP），旨在通过工作空间机制实现多场景隔离，支持任意领域的本体建模和分析决策。

### 1.2 本次实现范围

本次实现主要针对前端应用中尚未完整实现且无法正常使用的菜单功能，包括：

1. 工作空间管理功能
2. 数据摄入/采集功能
3. 生成图谱功能
4. 前端查询界面功能

## 二、设计与实现对比

### 2.1 工作空间管理功能

#### 设计要求（来源：docs/modules/workspace/DESIGN.md）

| 功能项 | 设计要求 | 实现状态 | 说明 |
|--------|----------|----------|------|
| 创建工作空间 | 支持创建新的工作空间 | ✅ 已实现 | 通过 POST /api/workspaces |
| 编辑工作空间 | 支持更新工作空间信息 | ✅ 已实现 | 通过 PUT /api/workspaces/{id} |
| 删除工作空间 | 支持软删除工作空间 | ✅ 已实现 | 通过 DELETE /api/workspaces/{id} |
| 切换工作空间 | 支持切换当前工作空间 | ✅ 已实现 | 通过 POST /api/workspaces/{id}/activate |
| 导入/导出 | 支持工作空间导入导出 | ✅ 已实现 | 通过 /api/import-export/export 和 /import |
| 权限控制 | 支持成员管理和权限配置 | ✅ 已实现 | 通过 /api/workspaces/{id}/members |
| 模板系统 | 支持工作空间模板 | ⚠️ 部分实现 | 后端支持，前端UI待完善 |
| 资源统计 | 支持资源使用统计 | ✅ 已实现 | 通过 /api/isolation/resource-usage/{workspace_id} |

#### 后端API实现情况

```python
# 工作空间 CRUD
POST   /api/workspaces                    # 创建工作空间
GET    /api/workspaces                     # 列出工作空间
GET    /api/workspaces/{workspace_id}      # 获取工作空间详情
PUT    /api/workspaces/{workspace_id}      # 更新工作空间
DELETE /api/workspaces/{workspace_id}      # 删除工作空间

# 状态管理
POST   /api/workspaces/{workspace_id}/activate     # 激活工作空间
POST   /api/workspaces/{workspace_id}/deactivate  # 停用工作空间

# 成员管理
POST   /api/workspaces/{workspace_id}/members/{user_id}     # 添加成员
DELETE /api/workspaces/{workspace_id}/members/{user_id}     # 移除成员

# 导入导出
POST   /api/import-export/export          # 导出工作空间
POST   /api/import-export/import          # 导入工作空间
GET    /api/import-export/records         # 列出导入导出记录
POST   /api/import-export/records/{id}/cancel  # 取消导入导出

# 隔离策略
POST   /api/isolation/policies                     # 创建隔离策略
GET    /api/isolation/policies/{workspace_id}     # 获取隔离策略
GET    /api/isolation/resource-usage/{workspace_id}  # 获取资源使用
POST   /api/isolation/enforce/{workspace_id}      # 执行隔离
```

#### 前端API调用

```typescript
// 工作空间管理
api.listWorkspaces()           // 列出工作空间
api.getWorkspace(id)          // 获取工作空间详情
api.createWorkspace(data)      // 创建工作空间
api.updateWorkspace(id, data)  // 更新工作空间
api.deleteWorkspace(id)        // 删除工作空间
api.activateWorkspace(id)      // 激活工作空间
api.deactivateWorkspace(id)    // 停用工作空间
```

#### 差异分析

1. **路径统一性问题**：前端原来调用 `/api/workspaces`，后端路由文件使用 `/api/workspace`，已统一为 `/api/workspaces`
2. **导入导出功能**：后端已完整实现，前端UI可以调用API进行导入导出操作
3. **模板系统**：后端已支持，前端界面尚未完全集成
